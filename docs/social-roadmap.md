# 소셜 기능 단계 설계

## 1차: 친구와 조력자

- 로비 `친구` 버튼은 친구 목록으로, 목록의 한 행은 공개 프로필로 이어진다. 공개 범위는 연구 레벨, 상태 문구, 최근 접속, 애착 렐릭으로 제한한다.
- 친구의 **애착 렐릭**만 조력자로 하루 3회까지 대여한다. 정상 대여 1회마다 대여자와 제공자에게 각각 친구 포인트 10을 지급하며, 제한 판정·양쪽 지급·사용 횟수 증가는 서버에서 하나의 처리로 확정한다.
- 조력자는 일반 스토리, 재료 콘텐츠, 일일 복원에만 허용한다. 고난도 스토리, 랭킹, 레이드/공동 보스에는 편성할 수 없게 해 클리어 가능 여부가 친구 보유에 종속되지 않도록 한다.
- 현재 `FakeSocialServer`와 `PREVIEW_FRIENDS`는 화면 흐름 검증용 임시 메모리 구현이다. 계정 서버 도입 시 UTC 일일 키, 대여 기록의 멱등 키, 제공자 오프라인 보상함, 친구 삭제/차단 시 정산 규칙을 서버 저장으로 옮긴다.

## 2차: 길드 — 활성 이용자 규모 확인 후

- 도입 조건은 친구 기능의 주간 활성 이용자와 반복 협동 의향이 확인되는 것이다. 길드는 **공동 발굴 기여도**, **길드 임무**, **공동 보스**만 포함하고 별도 경쟁 순위나 전용 성장 스탯은 만들지 않는다.
- 공동 발굴은 개인 기여와 길드 누적 보상을 분리하고, 길드 임무는 개인이 감당 가능한 목표의 합으로 구성한다. 공동 보스는 참여 보상을 중심으로 하며 특정 조력자나 과금 구성 보유를 입장·클리어 조건으로 삼지 않는다.
- 길드장 장기 미접속 시 위임 후보, 자동 위임 유예 기간, 해산 보호 기간을 길드 출시 계약에 포함한다.

## 채팅은 이번 단계에 포함하지 않음

- 1차와 2차 초기 범위에는 채팅을 추가하지 않는다.
- 이후 채팅을 추가하는 마일스톤에는 **신고**, **이용자 차단**, **금칙어/우회 표현 대응**, **제재 이력과 이의 제기**, **길드장 위임 정책**을 같은 출시 조건으로 묶는다. 안전 도구 없이 메시지 기능만 먼저 배포하지 않는다.
