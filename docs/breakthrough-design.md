# 한계 돌파 효과 설계 규칙

개체의 한계 돌파 효과(`RelicDef.breakthroughEffects`)를 새로 짜거나 고칠 때 **매번 먼저 읽는다.**
이 문서는 지금까지 합의된 규칙을 한곳에 모은 것이고, 어긴 흔적이 있으면 이 문서가 아니라 효과를 고친다.
규칙의 일부는 `tests/unit/breakthroughRules.test.ts`가 코드로 지킨다.

돌파 단계는 **II 평타 → III 궁극기 → IV 폭주 → V 패시브** 순으로 열린다(`BREAKTHROUGH_STEPS`). 슬롯마다 효과
**하나**를 두고, 한 효과는 읽히는 한 줄이어야 한다.

## 1. 진행 순서

1. **먼저 추천안을 표로 드리고 확인을 받는다.** 확인 전에는 구현하지 않는다. "구현하자"는 표를 승인한 뒤의 말이다.
2. 표에는 슬롯 · 효과 · 근거(스킬명·직군·포지션) · 점검할 것을 적는다.
3. 구현 전에 **기존 능력과 대조 점검**을 한다(아래 3). 점검에서 걸린 것은 구현 전에 표를 고친다.
4. 구현 → A/B 모의 → 수치 조정 → 결과를 숨김없이 보고한다(0에 가까운 슬롯도 그대로).

## 2. 무엇을 짜는가

- **직군이 하는 일을 대표한다.**
  - 탱커: 버티기·도발·제어(토리카). 전사: 순수 체급(렉시아). 지원가: 회복·보호막·팀 버프의 **분배**(도디·슈테·메테).
  - 암살자·원거리 딜러: **피해·기동·치명타·은신**(스피나·파루아).
- **암살자·원거리 딜러에게 생존 유틸(보호막·회복·몸 키우기)을 주지 않는다.** 은신 개념이거나 그 개체의 정체성
  (예: 마키 폭주)일 때만 예외다. 파루아의 폭주 보호막을 이 이유로 걷었다.
- **스킬명·외형·인게임 포지션을 근거로 삼는다.** 서사 텍스트는 전면 재점검 예정이라 있는 그대로 읽지 않는다.
  (메테는 음악 용어 — 스타카토·크레센도·아다지오 — 의 뜻을 따른다. 슈테는 유미처럼 아군에 붙는 지원가.)
- **수집형 게임에서 재미있을 요소를 고른다.** 수치 상향만으로 채우지 않는다. 토리카의 「세 개의 뿔」(주기), 「메아리」,
  「끝나는 순간 값을 치른다」, 렉시아의 「처치 재충전」처럼 **기존 계약에 얹는 간단한 메커니즘** 하나를 둔다.
  이미 있는 상태이상(독·둔화·경직·뇌진탕·출혈 등)과 규칙어를 재사용하면 구현이 간단하고 읽힌다.
- **「받는 피해 감소」는 쓰지 않는다**(`CLAUDE.md` 7번). 버티기는 눈에 보이는 자원(보호막·회복·대신 받기)으로 짠다.
- **화면 문구는 효과만 적는다.** 개발 의도·구현 상태를 설명하는 문장은 넣지 않는다(`CLAUDE.md` UI 규칙).

## 3. 기존 능력과의 대조 점검 (구현 전에 반드시)

효과가 **이미 0이거나 중복인지** 먼저 본다. 아래는 실제로 걸렸던 사례다.

| 점검 | 사례 |
|---|---|
| 기본 규칙이 그 값을 0으로 만들지 않는가 | 메테 찬가는 「잃은 체력 비례 회복」이라 **과회복이 없다** — 「넘치는 몫을 보호막으로」는 항상 0이었다. 비어 있는 몫(체력이 가득 찬 아군)에 건다. |
| 이미 상한에 닿는 값을 올리는 안이 아닌가 | 파루아 집중은 몇 번 쏘면 15겹이다 — 쌓는 속도·상한은 가치가 없다. 쏘는 양·값의 크기를 올린다. |
| 3대3 같은 일반 전투에서 발동하는가 | 갈래화살 인원 +2는 적이 셋뿐이라 효과가 없다. |
| 새 값이 누구의 행동에 묶여 쌓이는가 | 메테 크레센도 추가타는 **아군 누구의 평타든** 따라붙는다 — 팀 속도로 쌓이므로 상한을 둔다. |
| 같은 슬롯을 여러 경로가 공유하는가 | 메테의 보호막은 정화·궁극기가 같은 슬롯이다 — 전용 쿨다운으로 빈도를 묶는다. |
| 기존 값을 읽는 곳이 어디인가 | 궁극기 게이지(`def.ultimate.cost`)는 화면·자동 발동·재현이 직접 읽는다 — 코어 안에서만 줄이면 갈린다. 전투 스냅샷의 정의에 반영한다(`makeFighter`). |
| 기존 상태이상 규칙과 부딪히지 않는가 | 경직은 쌓일 때마다 저항(`gainTenacity`)이 오른다. 지속이 공격 간격보다 짧은지 본다. |
| 이미 다른 슬롯이 같은 말을 하지 않는가 | 도약 주기를 줄이는 효과를 II와 IV에 함께 두지 않는다. |

## 4. 하지 않는 것

- **궁극기 기절 시간을 늘리지 않는다. 궁극기 게이지 환급·충전·공속 누적으로 주기를 줄이지 않는다.**
  기절과 주기가 맞닿으면 한 적이 영원히 묶인다(스피나: 주기 3~5초 · 기절 3초). 기절을 가진 궁극기는
  같은 적에게 다시 걸리는 시간을 제한한다(`Skill.stunLockoutSeconds` — 스피나 8초).
  - 예외는 `breakthroughRules.test.ts`의 `CADENCE_APPROVED`에 **이유와 함께** 적는다(렉시아 처치 환급, 메테 게이지 −15).
- **폭주 단계(IV)는 궁극기를 건드리지 않는다. 폭주 중에만 궁극기가 달라지는 효과·궁극기를 쓴 순간이 조건인 폭주 효과를 짜지 않는다.**
  자동 전투는 궁극기를 게이지가 차는 즉시 쓰므로 폭주와 궁극기가 겹치는 타이밍을 사람도 모의도 잡거나 셈하기 번거롭고, 겹치는 판과 아닌 판의
  세기가 갈려 값이 흔들린다. 폭주 효과는 평타·이동·기본 능력 축에만 건다.
- **지원가의 회복 총량을 키우지 않는다.** 도디는 공속·평타 회복·궁극기 회복을 한 번씩 깎았다. 분배·보호막·비어 있는 몫으로 푼다.
- **발동이 드문 조건에 몫을 몰지 않는다.** 처치·사망·한 번뿐인 조건·폭주 한 번 동안의 효과는 모의에서 0으로 나온다
  (스피나 IV·V, 슈테 III·IV, 도디 II). 평타·궁극기처럼 자주 도는 축에 걸고, 드문 효과는 정체성(재미)으로 정당화한다.
- **효과를 걷는 대신 수치로만 메우지 않는다.** 걸린 항목은 이유를 `VERSION.md`에 남긴다(되돌린 기록).

## 5. 모의로 검증한다

- A/B 모의: 레벨 60 아군 셋 대 적 셋, 적 네 조합 × 30판, **돌파 0 대 V**(필요하면 단계별).
- 적 레벨은 55·60·68(필요하면 76·84)로 올려 바닥(승률 100%)에 닿지 않게 한다. 바닥에서는 이득이 보이지 않는다.
- 비교 기준: 토리카(SR 탱커) · 렉시아(SSR 전사) · 도디(R 지원가). 같은 등급이 아니어도 되지만 **너무 약한가**를 본다.
- 지표: 승률 · 잔여 체력 · (지원가) 본인 생존율 · (제어) 대상의 경직·기절 유지율 · 궁극기 사용 횟수.
- 효과가 모의에서 0이면 숨기지 않고 보고한다.

## 6. 구현 규약

- **돌파가 필요로 하는 전투 런타임 값은 `Fighter.bt`에 더한다. `Fighter`에 필드를 직접 더하지 않는다** — 전투원 객체 리터럴이 한계에 가까워, 최상위 필드 몇 개를 더하자 로스터 검수(`duelBalance`)가 3.6초에서 5.1초로 느려졌다(결과는 같았다).
- 타입은 `src/core/types.ts`의 슬롯별 유니온에 더하고, 전투는 `openedBreakthrough`로 열린 계약만 읽는다(개체 이름으로 분기하지 않는다).
- 새 `kind`는 `tests/unit/breakthroughRules.test.ts`의 `CATEGORY` 표에 분류를 적는다(안 적으면 컴파일 오류).
- 문구는 `skillPresentation.breakthroughEffectText`가 계약에서 조립하고, 한국어·영어·일본어 표(`src/i18n/*/skill.ts`)와
  나머지 여덟 언어 원고(`i18n-src/skill.json` → `scripts/build_translations.py`)에 함께 더한다. 규칙어는 `[[id|표기]]` 태그로 건다.
- 번역을 굽고 나면 `zh-Hant/data.ts`·`status.ts`의 불필요한 변경은 되돌린다. 새 글자가 들어오면 글꼴 서브셋을 점검한다.
- 단위 테스트를 `tests/unit/breakthroughEffects.test.ts`에 더한다. `npm run typecheck` · `npm test` · `npm run build`를 돌린다.
- `VERSION.md`에 **무엇을 왜**(수치 근거 · 걷어 낸 안과 이유 포함)를 적고, **main을 먼저, 작업 브랜치를 그 뒤에** 푸시한다.
