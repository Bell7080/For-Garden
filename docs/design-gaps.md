# 수집형 RPG 설계 공백과 구현 현황

세계관(`docs/lore.md`), 현재 코드, 경제·이벤트 설계 문서를 함께 대조한 2026-08-22 기준 현황이다.
프로토타입에서 동작한다고 해서 라이브 서비스 준비가 끝난 것은 아니므로 **구현 완료**와
**운영 과제**를 분리한다. 아래 완료 표의 `현재 한계`가 다음 단계의 경계다.

## 구현 완료

| 축 | 현재 구현 | 현재 한계 |
| --- | --- | --- |
| **저장** | `SaveManager`가 수집·성장·재화·천장·스토리·일일/주간 진행을 버전이 있는 JSON으로 저장하고 마이그레이션·검증·손상 복구를 맡는다 | 브라우저 `localStorage` 한정이다. 계정 연동, 기기 간 동기화, 서버 권위 검증과 충돌 해결은 없다 |
| **희귀도와 픽업** | R/SR/SSR 등급, 등급별 확률과 풀, 10연 SR 이상 보장, 등급/별 UI와 발굴 등급 연출이 연결돼 있다 | 배너 풀이 작고 운영 도구·확률 고지 화면이 없다. 현재 픽업은 같은 등급 안의 단순 확률 분기다 |
| **중복 각성** | 중복 획득은 0~5단계 각성을 올리고 단계별 전투 효과를 연다. 5단계 이후 중복은 공용 DNA 조각으로 환원한다 | 렐릭별 고유 각성 노드나 선택형 성장은 없고, 상한 이후 환원량도 고정 1개인 프로토타입 값이다 |
| **배너 그룹별 천장** | `pityGroupId`마다 SSR 100회 보장 카운터와 다음 SSR 픽업 확정을 저장하며, 같은 그룹의 교체 배너로 이월한다 | 픽업 확정은 **SSR 픽업 실패에만** 적용된다. SR 픽업 확정·교환형 확정권·시즌 종료/복각 이월 정책은 없다 |
| **유대** | 획득, 파티 승리, 하루 첫 로비 교류와 대사 선택으로 렐릭별 유대 경험치·레벨이 오르고 대사가 달라진다 | 0~10레벨의 공용 성장 규칙과 일부 전용 문구 수준이다. 유대 스토리·선물·풍부한 개체별 보상은 없다 |
| **야성** | 전투 중 게이지가 차면 단계별 피해 보너스를 받고, 유대가 높을수록 더 빨리 차며, 가득 찬 뒤에도 궁극기를 쓸 수 있다. 진압으로 게이지를 비울 수 있다 | 개체별 `ferocityTrait`는 현재 정보 표기 중심이고 전투 공식은 공용이다. 전용 연출·효과의 종류와 밸런스 검증이 부족하다 |
| **대사 시스템** | 정적 `DialogueStory`가 화자·본문·스탠딩·표정/모션·분기·선택 효과를 표현한다. 오프닝, 회상, 첫 대면, 이벤트 보고서와 일일 관찰 인터뷰가 같은 실행기를 쓴다 | 보이스, 자동 재생/로그/건너뛰기 같은 감상 기능과 충분한 캐릭터별 분량이 없다. 일일 관찰도 하루 한 렐릭의 제한된 질문 풀이다 |
| **일일 콘텐츠** | UTC 날짜 기준 하루 3회 제한인 `일일 복원`과 일일 로비 유대 보상, 일일/주간 임무 초기화가 저장된다 | `일일 복원`은 전투 없이 버튼 입력 즉시 치즈케이크를 받는 단일 항목이다. 스태미나 소비·난이도·소탕·보상 선택은 없다 |
| **도감과 발굴 연출** | 미보유 정보 은닉, 개체번호·발굴 기록, 즐겨찾기/애착 구분, 발굴→균열→등급 공개→첫 대면→결과 카드 순서가 구현돼 있다 | 플레이 가능 렐릭과 전용 아트·첫 대면 대사가 적고 도감 완성도 보상, 스킨·보이스는 없다 |

> `애착`은 로비 대표 한 명, `즐겨찾기`는 목록 필터용 여러 명, `유대`는 렐릭별 성장 수치다.
> 세 상태는 구현상 서로 독립되어 있으므로 이후 콘텐츠에서도 합치지 않는다.

## 남은 과제 — 구현 순서

### 1. 계정 서버 저장

- `GameApi`의 `FakeServer`를 인증된 HTTP 서버 구현으로 교체하고 계정·기기 간 저장을 동기화한다.
- 발굴 결과, 재화 차감, 보상 수령, 구매 제한, 이벤트 시각을 서버 권위로 확정한다.
- 멱등 요청, 낙관적 동시성/충돌 해결, 백업·복구와 운영 감사 로그를 마련한다.

### 2. 경제

- [`economy-design.md`](economy-design.md)의 월 공급 목표를 실제 일일·주간·이벤트 지급처에 연결한다.
- 스태미나 회복과 소비, 골드·보석의 실사용처, Heart Gem 제작/강화 및 성장 재료 획득처를 완성한다.
- 재화 유입·소비, 천장 분포와 DNA 잉여를 계측해 현재 프로토타입 수치를 조정한다.

### 3. 임무

- 현재 전투·발굴·급여·로비 행동을 세는 최소 일일/주간 목록을 운영 데이터형 목표와 보상 묶음으로 확장한다.
- 일일 진행도 단계 보상, 주간 완주, 스토리/도감/복귀 임무와 일괄 수령 UX를 추가한다.
- 이벤트 임무 정의를 실제 진행·수령 상태와 연결한다. 현재 첫 이벤트의 목표는 정적 연결 정보에 가깝다.

### 4. 상점

- 현재 재화 교환 카탈로그와 일/주/계정 구매 제한을 실제 서버 카탈로그·인벤토리로 옮긴다.
- 플랫폼 결제 영수증 검증, 가격 지역화, 환불/복구 구매와 상품 갱신 운영을 구현한다.
- DNA 교환소, 이벤트 교환소, 스킨 상품을 각각 알아볼 수 있는 탐색 구조로 정리한다.

### 5. 기간 이벤트

- [`event-content.md`](event-content.md)의 첫 이벤트처럼 스토리·스테이지·임무·교환소를 한 운영 단위로 끝까지 연결한다.
- 현재 큰바다쇠오리 1종, 보고서 1편, 전투 1곳, 목표 2개, 교환 상품 1개의 검증용 범위를 확장한다.
- 서버 시간표, 종료 정산, 복각/상시 기록 전환, 버전별 데이터 배포와 긴급 중단 절차를 마련한다.

### 6. 소셜

- 친구, 프로필, 우편과 선물함을 먼저 구현한다.
- 경제와 서버 검증이 안정된 뒤에만 서버 권위 스냅샷을 쓰는 비동기 방어전을 진행한다.
  재현·검증 경계는 [`asynchronous-arena.md`](asynchronous-arena.md)를 따른다.
- 길드·실시간 협동은 1인 개발 범위를 넘기 쉬우므로 초기 출시 필수 범위에 넣지 않는다.

### 7. 장기 발굴 콘텐츠

- 렐릭 수와 전용 스탠딩·SD·대사·야성 효과를 늘려 수집 풀이 반복을 견디게 한다.
- 스토리 챕터, 공멸 습격, 상시/복각 발굴 기록, 고난도·무한 도전을 단계적으로 추가한다.
- 파티 프리셋, 자동 전투, 소탕과 도감 완성도 보상으로 누적 콘텐츠의 반복 피로를 줄인다.
- 스킨·의상, 보이스, 캐릭터 테마 BGM과 로비 반응/대기 모션은 콘텐츠 생산 파이프라인이 안정된 뒤 확장한다.

## 범위 판단

지금은 수집형 RPG의 최소 규칙이 없는 상태가 아니라, 그 규칙이 **한 브라우저 안에서 검증된
프로토타입**인 상태다. 따라서 새 규칙을 넓히기보다 계정 서버 저장을 먼저 세우고, 경제 → 임무 →
상점 → 기간 이벤트가 같은 서버 경계를 공유하게 만든 뒤 소셜과 장기 콘텐츠로 넘어간다.

# 후속 대체물 추적

아래 항목은 임시 구현이지만 전용 서버·원화·편성 데이터가 준비되기 전까지 런타임에서 삭제하지
않는다. 정식 대체물이 병합된 항목만 같은 변경에서 참조와 임시 구현을 함께 제거한다.

- `src/api/FakeSocialServer.ts`, `src/data/friends.ts`: 계정·친구 서버와 공개 프로필 DTO 구현 대기.
- `src/puppets/tints.ts`, `torika-placeholder` 참조: 각 렐릭의 전용 전신/SD 원화 연결 대기.
- `src/data/stages.ts`의 고정 적 편성: 스테이지별 운영 편성 데이터 연결 대기.
