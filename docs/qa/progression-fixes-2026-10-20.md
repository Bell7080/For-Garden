## 검증

- 마지막 전체 단위 검사: 350개 파일, **3,982 통과 / 1 skip**. 모든 묶음에서 타입 검사와 프로덕션 빌드를 실행했다.
- 배포 스크립트를 임시 checkout에서 실행해 서버→클라이언트 순서, 서버 생성 실패 시 종료 코드 보존과 클라이언트 빌드 중단을 확인했다.
- 실제 서버 처리기를 production 규칙·strict 모드로 실행해 **전투 41개, 이야기 45개**를 연속 진행했다. 호출마다 JSON 저장 왕복과 새 규칙 인스턴스를 사용하고, 완료 재전송이 중복 지급하지 않는지 확인했다. 레벨 60 검사 계정이며 난이도/운영 DB 검사는 아니다.
- 재생성한 배포 후보 번들의 실제 처리기로 교류 **8도시 수령 모두 통과**했다.
- 브라우저 집중 회귀: 설정·발굴 재진입·상점·연구 결과판 4개 통과. 별도 1-2 승리→보상→후속 대사→지도 복귀와 두 완료 ID의 저장도 통과했다.
- 신규 SSR 소개를 반드시 거치는 연구 회귀도 통과했다. 실제 천장 직전 계정으로 소개를 보장하며 난수/연출을 대체하지 않는다. test 모드의 기존 결과판 경로이며 운영 모드의 WebGL2 연구 시네마틱은 별도 검증 대상이다. 지원 언어 12개 전체의 1.3배 타이틀 검사도 통과했다. 실제 선택 입력·문구 폭 진단·계정 확인창 진입을 사용했다. 세 차례 집중 브라우저 실행은 각각 4/4, 1/1, 2/2 통과했다.
- 격리된 임시 PostgreSQL에서 전체 마이그레이션과 출시 초기화의 건수 보고·가드 5종·분류 누락 감지·실행·점검·재실행·우편/쿠폰 보존 모드가 모두 통과했다. 최신 재화 조정 표의 누락된 검사 표본을 보완했다.

## 서버/저장 계약

- 원격 API가 전체 Session을 revision 순서로 반영한다. Manager/UI는 원격 영수증의 오래된 지갑·가방·슬롯을 현재 상태로 다시 복사하지 않는다. 지급 사실과 현재 스냅샷은 별개다.
- 충전이 불명확하면 같은 API 연결에서 창을 다시 열어도 같은 명령 ID를 회수한다. 서버의 내부 영수증도 같은 충전 명령을 한 번만 차감한다. 성공/규칙 거절 뒤에만 다음 명령을 만든다.
- 이야기 선택은 서버 카탈로그의 식별자와 진행 경로만 허용한다. `serverJournal.storyChoices`는 노드별 최초 선택, `pendingStoryBondXp`는 미보유 렐릭 유대 적립이다. 최초 획득과 같은 저장에서 적립분을 지급·제거한다. 새 획득 경로도 `redeemDeferredStoryBond`를 호출해야 한다.
- 두 장부는 기존 JSON의 선택 필드다. **새 SQL 마이그레이션이나 환경 변수는 없다.** 구 저장은 빈 장부로 호환된다.
- 과거에 이미 완료됐지만 유대가 누락된 계정은 선택 기록이 없어 답을 추측해 소급 지급하지 않는다. 보정이 필요하면 별도의 일회성 보상 기준과 중복 방지 기록을 정해야 한다.

## 범위

브라우저 검사는 test 모드 FakeServer 경로이며 iPhone/Pixel도 Chromium 화면 프로필이다. 운영 Supabase에 실제 로그인한 E2E, 실제 iOS Safari, Vercel 배포 완료 자체를 증명하지 않는다. 기존 전체 171건의 감사 집계와 이번 집중 재검사를 혼합해 “최신 전체 E2E 통과”로 표현하지 않는다. 업적·길드 진입점과 미정 PvP 기획은 유지한다.
