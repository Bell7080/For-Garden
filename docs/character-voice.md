# 캐릭터 목소리 점검 — 세계에 사는 사람으로 읽히게

대사는 설정을 전달하는 문장이 아니라 **그 사람이 그 자리에서 하는 말**이어야 한다. 이 문서는 대사를
쓰거나 고칠 때의 기준과, 그 기준을 반복해서 적용하는 점검 절차(도구 포함)를 한 곳에 모은다.
양식 자체(관찰 일지·질문·애착 스토리의 틀)는 `docs/character-story-design.md`가 갖는다.

## 1. 기준 (사용자가 정한 방향)

- **하나의 인격체로, 개성 있게. 그러나 은근하게.** 성격을 붙이려고 소품·버릇·말버릇을 덧씌우지 않는다.
  개성은 무엇을 말하느냐보다 **무엇에 신경 쓰고 무엇을 흘려 넘기느냐**에서 읽힌다.
- **이상한 핀트에 집착하지 않는다.** 한 개체가 깃털·사탕·시말서처럼 한 소재에만 계속 돌아오면 사람이
  아니라 설정표로 읽힌다(유티의 깃털이 그 사례다). 소재는 한 개체당 **여러 레벨에 걸쳐 되풀이하지 않고**,
  꼭 필요한 하나가 있다면 **서로 다른 면**으로만 다시 꺼낸다.
- **실제로 있을 법한 말과 행동.** 소리 내어 읽었을 때 그 사람이 정말 그렇게 말할지, 그 상황에서 그
  행동을 할지를 본다. 수집형 RPG의 매력적인 한마디처럼 **짧고, 말맛이 있고, 한 줄에 그 사람이 읽혀야** 한다.
- **인위적인 캐릭터성을 덧칠하지 않는다.** 웃음소리·말끝·특이한 습관은 하나만, 있어도 눈에 띄지 않을 만큼.

## 2. 고치는 대상 (점검표)

| 증상 | 예 | 처방 |
| --- | --- | --- |
| 소재 반복 | 시말서·문·사탕이 여러 레벨에 | 한 레벨만 남기고 일상적인 한마디로 바꾼다 |
| 자기 해설 | "저는 ~한 사람이에요", "제 특기는…" | 행동이 보이는 말로 바꾼다 — 설명하지 않고 보여 준다 |
| 성장 서사 낭독 | "이제는 조금 편해졌어요", "용기를 냈어요" | 변화는 말투의 거리(호칭·말끝·침묵)로만 보인다 |
| 다른 개체·사건 의존 | "도디가 상자를 옮길 때…" | 혼자 눌러도 통하는 말로. 이름은 꼭 필요할 때 한 줄만 |
| 시간선 누수 | 레벨 7이 장 8의 사건을 미리 말함 | 그 레벨까지 지난 장의 사건만 |
| 친밀도 곡선 | 레벨 0이 이미 가깝거나, 레벨 10이 낯섦 | 호칭·거리·반말 허용을 레벨에 따라 천천히 움직인다 |
| 말투 위계 어긋남 | 같은 개체가 해요체와 반말을 오감 | 그 개체의 기본 위계를 정하고 지킨다. 바뀌면 이유가 있어야 한다 |
| 점원·투영 대사 | 투영 몸이라는 사정을 억지 농담으로 | 상점·값·연구원과의 관계에서 나오는 말로 |
| 어색한 한국어 | 번역투, 어울리지 않는 어미 | 소리 내어 읽어 걸리는 곳을 고친다 |
| 규칙 위반 | 스쿼드 담당·역할을 대사에 풀기, 옷 장식을 몸의 반응으로, 연구원 성별 지정 | `CLAUDE.md`의 「렐릭 이야기 묶음」 규칙 |

## 3. 절차 (한 개체 또는 한 묶음)

1. **기계 점검** — `python3 scripts/voice_audit.py [개체...]` 가 셀 수 있는 신호(소재 반복·자기 해설체·
   다른 개체 의존·시간선·성별 의심)를 보고서로 낸다. 신호는 후보일 뿐 판정이 아니다.
2. **읽고 판단** — 보고서를 근거로 그 개체의 파일(`src/data/relicStories/<id>.ts`)을 처음부터 읽고
   목소리를 파악한 뒤, 위 점검표로 줄 단위로 고른다. **멀쩡한 줄은 건드리지 않는다**(개체당 1/3 안팎이 상한).
   병렬로 돌릴 때는 개체 5~6명씩 묶어 검수 에이전트에 맡기고, 결과는 저장소가 아닌 별도 JSON(`old`·`new`·`why`)으로
   받는다. `old`로 찾아 바꾸면 위치 기준(0/1부터)이 갈려도 안전하다.
3. **한국어 반영** — 줄 수·레벨 구조·키는 그대로 두고 문장만 바꾼다. 바꾼 키의 목록을 남긴다.
4. **열한 언어 재번역** — 바뀐 키만 번역 지침(개체의 기존 `researcherTitle`·목소리 유지, 연구원 성별 중립)으로
   다시 옮기고 `i18n-src/*.json`·`src/i18n/en|ja`에 넣는다. `scripts/build_translations.py` → zh-Hant 파생 →
   새 글자는 `scripts/patch_font_glyphs.py`.
5. **검증** — `npm run typecheck`, `npx vitest run`(용어집 테스트 포함), `npm run build`.
6. **기록** — `VERSION.md`에 한 항목.

## 4. 점검 범위 (목소리가 사는 곳)

| 자리 | 파일 | 비고 |
| --- | --- | --- |
| 클릭 대사(유대 대사) | `relicStories/<id>.ts`의 `bondLines` | 레벨 0~10 × 3~4줄. 가장 자주 읽힌다 |
| 첫 만남 한마디 | `src/data/relicFirstMeetings.ts` | 소개 장면의 첫 줄 — 목소리가 한 줄로 읽혀야 한다 |
| 마일리지 점원 | `src/i18n/ko/shop.ts` `mileage.clerk.*` | 투영으로 서 있는 개체가 건네는 말 |
| 상점 점원 | `src/data/shopPresentation.ts` + 문구 표 | 오비·프로티아·하이네·록스우·글리아 |
| 관찰 일지·질문·애착 스토리 | `relicStories/<id>.ts` | 서술이 길어 소재 집착이 일지·장 대사로 새기 쉽다 |

## 5. 발전시키는 법

- 점검에서 새 증상이 나오면 **점검표에 한 줄**을 더하고, 셀 수 있으면 `scripts/voice_audit.py`에 신호로 옮긴다.
  새 규칙을 대사 파일 주석에 흩어 두지 않는다.
- 새 개체의 대사를 처음 쓸 때 이 문서를 먼저 읽고, 쓴 뒤 같은 도구로 한 번 돌린다.
- 도구가 너무 많이 걸면(소재 반복의 임계 `REPEAT_LEVELS`, 흔한 말 `STOP`) 값을 조정하되 이유를 이 문서에 남긴다.
