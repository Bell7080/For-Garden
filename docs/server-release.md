# 서버 마무리 적용 안내

이 변경은 길드를 포함하지 않는다. 길드는 Claude의 구현 이후 연결한다.

## 적용 순서

1. 기존 `20261017150000_server_state.sql`까지 적용된 프로젝트에 `supabase/migrations/20261018000000_server_release.sql`을 먼저 적용한다.
2. 적용 성공과 서비스 롤 RPC 권한을 확인한 뒤 이 변경의 `npm run build:server` 산출물과 클라이언트를 같은 버전으로 배포한다.
3. 서로 다른 실제 계정 두 개로 친구 신청/상호 수락, 친구의 소환 레이드 노출, 기여도와 공유 체력, 정산을 확인한다.
4. 운영 코드에 서버 키를 넣지 않는다. 기존 Vercel 서버 환경 변수 `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, 공개 인증 키를 사용한다.

**마이그레이션 전에 새 서버 코드를 배포하면 새 RPC가 없어 503이 발생한다.** 이 작업 환경에는 Supabase 관리 도구/키가 없어 운영 DB 적용과 실계정 검증은 별도 단계다. SQL은 격리된 PostgreSQL 16에서 검증했다.

## 구현 범위

- 친구 API를 `/api/game`의 `social.*` 요청으로 연결한다. 서버는 JWT의 사용자 ID만 주체로 삼고, 클라이언트의 selfUid/playerId로 권한을 정하지 않는다.
- 목록/검색/추천/신청/취소/수락/거절/일괄 처리/즐겨찾기/삭제/조력자 대여를 DB에서 처리한다. 상호 신청은 친구가 되고, 삭제는 양쪽 관계를 해제한다.
- 공개 프로필은 서버가 화이트리스트로 생성한다. 공개 UID는 `players.uid`이며 재화·전체 편성·저장 본문은 공개하지 않는다.
- 대여는 UTC 일일 3회, 양쪽 포인트 지급, 사용 횟수, 멱등 영수증을 같은 DB 트랜잭션으로 확정한다.
- 공유 레이드는 월드/친구 소환/내 소환/참여한 판만 노출한다. 다른 계정의 검증된 기여를 집계하며 가짜 참가자/시간 기반 피해 곡선을 운영 서버에서 사용하지 않는다.
- 계정 저장, 요청 영수증, 공유 레이드 체력·시도·정산 표식은 단일 트랜잭션이다. 계정 revision 또는 공유 레이드 revision 충돌 시 전체를 취소하고 다시 읽는다.
- 일반 전투·대작전·현상수배·원정 교전은 서버 발급 전투 스냅샷/시드와 20ms 고정 틱을 사용한다. 궁극기를 누른 틱만 제출하고 서버가 평타·표적·피해·HP·승패를 다시 계산한다.
- 원정/레이드 보스는 v2 재현만 허용한다. 레이드 난수 시드도 입장 때 서버가 정한다. 서버 시계보다 빠른 종료와 대량 행동을 거절한다.
- 비용이 결과에서 차감되는 기존 기획을 유지하면서 입장 영수증을 서버 저장에 보존한다. 완료 결과의 승패·HP·완료 라운드는 클라이언트 값 대신 검증 결과를 사용한다.
- 쓰기에는 외부 requestId가 필수다. 영수증은 메서드/인자에 묶이며, 상태 변화가 없는 쓰기도 영수증을 저장한다.
- 요청 크기 128 KiB, 인자 개수, 메서드 allowlist, 계정별 전체 300회/분 및 메서드별 읽기 180/쓰기 60회/분, 검색 20회/분을 DB에서 강제한다. 초과 응답은 429와 Retry-After다.
- 정식 클라이언트는 로컬 세이브 업로드로 서버 계정을 초기화하지 않는다. 서버가 시작 상태를 생성한다. 설정/인증이 없거나 서버가 실패하면 로컬 경제로 조용히 이어 가지 않는다.
- 기존 QA 도구/표본은 QA 빌드에 남긴다. 운영 HTTP에는 개발 메서드를 등록하지 않으며 일반 번들의 QA 저장/디버그 분리는 기존 검증을 유지한다.

## 검증

- `npm run typecheck`, `npm test`, `npm run build`, `npm run build:server`.
- 정식 산출물의 `npm run test:build-isolation`, `npm run test:release-fixtures`.
- 단위 회귀: `serverRelease`, `serverHttpBoundary`, `remoteSocialApi`, 기존 `gameHandler`, `serverProgress`, `raid`.
- PostgreSQL: `npm run test:server-db` (Docker, `postgres:16-alpine` 필요). 외부 네트워크 없는 임시 컨테이너를 생성·제거하며 실제 동시 요청과 DB JSON→정식 SaveManager 호환성도 확인한다. 내부 SQL은 `supabase/tests-server-release.sql`. **격리된 테스트 DB 전용**이며 테스트 데이터를 ROLLBACK한다. 기존 Supabase 역할/players/player_saves 스키마와 마이그레이션이 필요하다.
- 실사용자/운영 DB·실기기·전체 E2E는 이 검증을 대체하지 않으며 별도로 확인한다.

## 후속 항목과 운영 주의

- 웹 토큰 보관은 여전히 `webTokenStore.ts`의 출시 차단 항목이다. 웹 정식 출시 전 HttpOnly 세션 또는 앱의 키체인/키스토어로 전환해야 한다.
- 실제 결제 영수증/광고 SSV 공급자 연결과 길드는 이번 범위 밖이다. 미연결 검증을 성공으로 간주하지 않는다.
- 서버 규칙이 바뀐 배포 전 전투/구형 보스 입장은 새로 입장해야 할 수 있다. 서버 입장 메타데이터가 없는 과거 진행을 임의로 완료 처리하지 않는다.
- 초기 규모의 소셜 관계 변경은 전역 DB 잠금으로 상한을 보호한다. 요청 영수증/속도 제한/끝난 레이드의 보존·정리 작업과 동시 접속 규모에 따른 성능 측정은 운영 정책으로 정해야 한다.
- 앞서 점검한 연출 접근성/품질 설정 연결은 별도 미완료 작업으로 유지한다.
