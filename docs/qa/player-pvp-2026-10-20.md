# 실제 계정 PvP·경쟁 보상 — v0.321.0

## 원인과 동작

기존 정식 빌드는 `duelNpcPool`의 표본을 제거했지만 실제 방어덱 조회/결투 입장/정산은 연결하지 않았다. `DuelScene`은 빈 목록에서 도전 버튼을 비활성화했다. 0점이나 게스트 제외 조건이 원인은 아니었다.

- 해금(연구원 레벨 6)된 활성 계정은 수동 등록 없이 기본 파루아·토리카·도디 방어덱으로 참가한다. 0점·익명 계정도 포함한다. 기존 저장에서도 바로 읽으며, 별도 PvP 입장 이력이 필요 없다. 자신·미해금·정지/차단/삭제 계정은 제외한다.
- 실제 보유/성장/룬/유대를 읽고, 입장 때 양쪽을 고정한다. 공용 `prepareCombat`/`finishCombat`으로 서버가 재현한 승패만 정산한다. 클라이언트가 보낸 `won`은 신뢰하지 않는다.
- 공격자 지급·방어자 점수/전적·요청 영수증은 같은 트랜잭션이다. 양쪽 저장 revision이 바뀌면 전체를 재시도한다. 입장 도전권은 한 번만 차감되고, 정산 재전송이 방어 기록을 중복 반영하지 않는다.
- 상대가 적은 베타에서도 새로고침이 목록을 비우지 않는다. 상대가 전혀 없으면 안내를 표시하고 다시 조회할 수 있다.
- 원정 주간 최고 기록은 실제 서버 순위에 연결했다. 동점은 먼저 달성한 기록, 그다음 계정 ID로 결정한다.

## 보상 정책

공통 주간 젬: 1위 5,000 / 2~3위 4,000 / 4~10위 3,000 / 11~50위 2,000 / 51~100위 1,500 / 나머지 참가자 800. PvP와 원정 각각 지급하며 원정 인양 기록은 기존 400/320/250/180/130/80을 유지한다.

월요일 00:00 UTC(한국·일본 월요일 09:00)에 마감한다. PvP의 미대전 0점 계정도 목록/실시간 순위에 표시하지만, 주간 보상은 해당 주 실제 대전(방어 포함) 또는 원정 점수를 남긴 참가자만 받는다. 마감 주 순위는 최초 정산 시 전체 고정하고, 접속 시 일반 우편함에 발송한다. 우편은 발송 후 30일이며 계정·종목·주차의 고유 키로 중복을 막는다. 별도 cron 설정은 필요 없다.

PvP 시즌: 21일, 기준은 기존 월요일 2026-01-05 00:00 UTC. 종료 점수의 60%를 100점 단위로 내린다(1,200→700). 시즌 보상 젬은 브론즈 500 / 실버 1,000 / 골드 2,000 / 플래티넘 3,000 / 다이아몬드 4,000 / 마스터 5,000 / 그랜드마스터 6,500 / 챌린저 8,000. 기존 휘장과 최초 도달 보상은 유지한다. 시즌 보상은 대전 기록이 있는 시즌의 종료 티어로 한 번 수령한다.

현재 연구 1회는 300젬이다. 주간 1위는 약 16.67회, 두 종목 1위는 33.33회다. 두 종목에서 3주 연속 1위+플래티넘 시즌 보상은 33,000젬(110회)이다. 이는 요청한 기준에 맞춘 초기 운영값이며 보편적인 업계 표준값을 주장하지 않는다. 뽑기 확률은 변경하지 않는다.

## DB 적용·배포

기존 마이그레이션 뒤 다음 두 파일을 순서대로 적용한 후 서버/클라이언트 v0.321.0을 배포한다.

1. `supabase/migrations/20261026000000_player_duels.sql`
2. `supabase/migrations/20261027000000_competitive_weekly.sql`

기존 Supabase URL·서비스 키를 그대로 쓰며 추가 제공자/환경 변수/스케줄러 설정은 없다. RPC/경쟁 표는 service_role 전용이며 anon/authenticated의 직접 접근은 금지한다. 운영 DB 적용과 실제 Vercel 배포 확인은 이 환경에서 수행하지 않았다. 기존 28일 주기에서 21일 주기로 전환하는 첫 접속은 이전 저장 시즌을 한 번 정산한다.

새 경쟁 표 세 개를 출시 초기화 두 스크립트의 reset 목록에 추가했다. **해당 초기화 스크립트를 기능 적용 목적으로 실행하지 않는다.** 기능 적용은 위 마이그레이션 두 개만 실행한다.
