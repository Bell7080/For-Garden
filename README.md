# Eternal City (for-garden)

세로형 모바일 수집형 RPG. 멸종한 DNA를 되살린 호문쿨루스 소녀 **RELIC**들이 사는
"이터널 시티"에 유일한 연구원(주인공)이 입주하며 그들을 관리해 나가는 이야기.

소녀전선 스타일의 코어 컨텐츠, 니케 스타일의 세로형 화면, 림버스 컴퍼니 같은 인디 감성을
목표로 한다. 1인 개발로 감당 가능한 범위를 우선한다.

## 현재 상태

코어 전투 루프의 첫 형태가 돈다.

`타이틀 → 연구소 → (출격) → 스테이지 지도 → 파티 편성 → 전투 → 결과`

- **스테이지 지도**: 세로 게임이므로 진행 경로가 아래에서 위로 뻗는다. 1-1부터 1-5까지 있고,
  직전 스테이지를 깨야 다음이 열린다.
- **파티 편성**: 위쪽에 이번 전투의 전장을 그대로 축소해 보여준다. 적 진형에서 누가 선봉인지
  들어가기 전에 눌러 확인할 수 있고, 내가 고른 렐릭이 어느 자리에 서는지도 함께 보인다.
  아래쪽 보유 렐릭 그리드는 짧게 누르면 편성, **꾹 누르면 상세 정보**다.
- **전투**: 적은 우상단, 아군은 좌하단에 각각 삼각형으로 서서 비스듬히 대치한다. 전방에 선
  쪽이 상대를 향해 튀어나온 꼭짓점이다.

아트 리소스는 아직 없어서 도형과 글자로만 그린다. 스탠딩/SD 일러스트가 들어갈 자리다.

### 전투 화면 조작

- **좌하단 리볼버**: 교대할 렐릭 3명이 원형으로 서 있고 맨 위가 출전 중이다. 아래 두 명 중
  하나를 누르면 실린더가 돌 듯 자리를 바꿔 선봉으로 올라온다.
- **우측**: 위에서부터 적 정보 · 궁극기 · 기본 공격.
- **`?` 아이콘**: 렐릭과 스킬 위에 붙어 있다. 누르면 정보창이나 스킬 툴팁이 열린다.

정보창은 `src/ui/info.ts`의 `InfoManager`가 전담한다. 아군이든 적이든, 편성 화면이든 전투
중이든 **능력치 · 패시브 · 기본 공격 · 서포트 · 궁극기**를 언제나 같은 순서로 낸다. 화면마다
정보 형식이 갈라지지 않게 하려는 것이다.

### 전투 규칙

턴제로 주고받는다. 한 턴에 아래 셋 중 하나를 고른다.

| 행동 | 설명 |
| --- | --- |
| 기본 공격 | 선봉이 적 선봉을 친다. 궁극기 게이지가 찬다. |
| 궁극기 | 게이지가 다 차야 쓸 수 있는 강한 공격. |
| 교대 | 후방과 선봉을 맞바꾼다. |

교대도 한 턴을 쓰고, 게다가 **교대한 다음 턴에는 다시 교대할 수 없다**. "강한 공격은 탱커로
막고 때릴 때 교대한다"는 판단에 대가를 붙이기 위해서다. 선봉이 쓰러지면 후방이 자동으로 앞에 선다.

패시브는 세 종류를 엔진이 해석한다 — 전방에서 받는 피해를 줄이는 `frontGuard`, 교대 직후
첫 공격을 강화하는 `swapMomentum`, 후방에 있는 동안 매 턴 선봉을 회복시키는 `rearMend`.
후방 2명은 지금 이 패시브로 전투에 관여한다.

전투 엔진(`src/core/battle.ts`)은 난수를 쓰지 않는다. 같은 입력이면 같은 결과가 나와서
규칙을 테스트로 고정할 수 있다.

#### 서포트에 대해

후방에서 적을 직접 때리는 "서포트 공격"은 뺐다. 회복 · 공격력 버프 서포트는 엔진과 렐릭
데이터에 그대로 남아 있고 테스트도 붙어 있지만, **지금 조작부에는 버튼이 없다** — 하단이
궁극기와 기본 공격만 두는 배치라서다. 한쪽만 쓸 수 있으면 규칙이 기울기 때문에 적 AI도
서포트를 쓰지 않게 맞춰 뒀다. 다시 넣을 때는 `decideEnemyAction`의 주석과 조작부를 함께 되돌리면 된다.

## 기술 스택

- Phaser 3 + TypeScript + Vite
- 기준 해상도 1080×1920 (9:16), `Phaser.Scale.FIT`으로 축소·중앙 정렬
  - 데스크톱의 넓은 창: 좌우 레터박스로 세로 화면이 그대로 축소되어 보인다 (컴퓨터 테스트용)
  - 모바일 기기가 실제로 가로로 눕혀졌을 때만 회전 안내 오버레이가 뜬다
    (`pointer: coarse` + `orientation: landscape` 조합으로 감지, `src/style.css`)
- [PuppetForge (WebGLE)](https://github.com/Bell7080/WebGLE)를 `puppetforge` 패키지로
  git 의존성 설치 — 이후 캐릭터 스탠딩/전투용 종이인형 애니메이션을 여기서 가져다 쓴다.
  설치 시 `prepare` 스크립트가 자동으로 `dist-lib`를 빌드하므로 별도 설정이 필요 없다.

## 스크립트

```bash
npm install       # puppetforge git 의존성도 함께 빌드된다
npm run dev        # 로컬 개발 서버 (컴퓨터 브라우저로 세로 화면 확인)
npm run build      # tsc --noEmit + vite build
npm test           # Vitest (코어 로직)
npm run typecheck
npm run test:e2e   # Playwright — 모바일 화면비/터치로 빌드 결과 구동 확인 (build 이후 실행)
```

## GitHub Actions로 구동 확인

실제 모바일 기기 없이도 `.github/workflows/ci.yml`이 매 push/PR마다:

1. 타입체크 → Vitest → 빌드
2. iPhone 14 / Pixel 7 화면비로 Playwright가 빌드 결과를 실제로 띄워
   - 캔버스가 세로로 렌더링되는지
   - 탭(터치) 입력으로 타이틀 → 연구소 씬 전환이 되는지
   - 기기를 가로로 눕히면 회전 안내가 뜨는지
   를 확인하고 스크린샷을 아티팩트로 남긴다.

로컬에 모바일 기기가 없다면 Actions 실행 결과의 `mobile-screenshots` 아티팩트로
실제 화면을 확인하면 된다.

## 배포 (Vercel)

배포는 이 CI가 아니라 **Vercel의 GitHub 연동**이 맡는다. `vercel.json`에 빌드 설정을
미리 넣어뒀지만, Vercel 쪽 저장소 연결(Import)은 계정 인증이 필요해 아래 절차를
Vercel 대시보드에서 직접 한 번 해야 한다.

1. https://vercel.com/new 에서 GitHub 계정으로 로그인 → `Bell7080/For-Garden` Import
2. Framework Preset은 Vite로 자동 인식됨 (`vercel.json`이 있으면 그대로 따른다)
3. 이후로는 `main`에 push할 때마다 Vercel이 자체적으로 빌드·배포한다 (PR에는 미리보기
   배포 URL이 자동으로 달린다) — 이 저장소의 GitHub Actions와는 완전히 별개로 동작하므로,
   Playwright e2e처럼 느린 잡 때문에 배포가 지연되지 않는다.

CI(`ci.yml`)는 타입체크·테스트 품질 게이트로만 남겨뒀다. GitHub Pages 배포 잡은 제거했다.

## 구조

```text
src/
  config/     # 기준 해상도 등 상수
  core/       # 전투 규칙과 타입. Phaser를 전혀 모른다 (Vitest 대상)
  data/       # 렐릭 · 스테이지 정의. 밸런스는 코드가 아니라 여기서 만진다
  state/      # 씬 사이를 오가는 진행 상태
  scenes/     # Phaser 씬 (그리기와 입력만)
  ui/         # 버튼 · 유닛 패널 · 리볼버 · 정보창 매니저 · 색과 글꼴 토큰
  debug.ts    # E2E가 씬 전환과 전투 상태를 확인하기 위한 window 훅
tests/
  unit/       # Vitest — 전투 규칙
  e2e/        # Playwright — 모바일 화면비 + 화면 흐름
```

의존 방향은 `scenes → core`, `scenes → data` 한 방향이다. `core`는 렌더러를 모른다.
