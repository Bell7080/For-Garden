# 던전·광고 일자·계정 전환 및 원정 경제 — v0.323.3

## 변경

- 치즈케이크 결과 확정 영수증은 전투 인스턴스에 보관한다. 서버 확정 후 결과판 표시가 실패해도 같은 전투에서는 지급 API를 재호출하지 않는다. 이전 전투의 늦은 응답도 새 결과판을 열지 않는다. 결과 SD에는 소환수가 아닌 편성 렐릭만 표시한다. 표시 실패는 서버 저장 실패와 진단 단계를 구분한다.
- 서버 `snapshot`이 UTC 광고 일자를 정산한다. 소탕 창을 열 때 최신 서버 상태를 받아, 전날 소진한 카운터로 새날 광고 버튼을 잠그지 않는다. 기존 초기화 기준인 UTC 00:00(한국 09:00)을 유지한다.
- 설정의 계정 조작은 예외에도 입력 잠금을 해제하고 재진입 때 입력·busy 상태를 초기화한다. 로그아웃 전 시작한 인증 응답은 로그인 상태를 되살리지 않는다. 이전 연결의 친구·길드 API도 연결 세대를 확인한다. 게임 API의 전체 네트워크 대기는 재시도를 포함해 35초로 제한하며 미확정 쓰기의 재시도 ID는 유지한다.

달성 보상은 `claimExpeditionReward({stageId:'all',requestId})` 한 요청으로 현재 달성한 미수령 단계만 저장한다. 지급·단계 표식·영수증을 함께 확정하고 실제 지갑 상한 적용량만 반환한다. 구형 단일 단계 요청은 유지한다. 화면은 같은 재화를 합쳐 보상 팝업 하나로 보여 준다.

업적·일간/주간 임무·연구도 젬은 5배다. 일간 임무와 연구도의 젬 총량은 350, 주간은 900이다. 기존 목표·단계 ID·수령 이력을 보존하며 이미 받은 단계의 소급 재지급은 하지 않는다. 과거 최고 점수·현재 진행 중인 런의 확정 점수도 삭제하거나 재계산하지 않는다. 새 노드·새 보스 제출부터 새 점수 계수를 쓴다. 기존 주간 기록 주기와 일일 입장 정책은 바꾸지 않는다.

## 검증 범위

- 서버 직렬화 왕복: 치즈케이크 1·8단계 입장→발급→전투 검증→결과→재조회.
- 격리 PostgreSQL: 위 던전 경로, 결과 응답 유실 후 재전송, 기존 스토리·레이드·원정 저장/복귀·동시성 검사.
- 광고 UTC 자정 전후 조회·직렬화·재실행·다음날 수령.
- 계정 예외 후 재시도, 중복 조작 차단, 이전 씬 응답 무시, 로그아웃과 토큰 갱신 경합.
- 원정 일괄 지급의 저장 실패 원자성·재접속·중복 수령 방지·지갑 상한 및 통합 팝업.
- 운영에 남은 치즈케이크 발급표를 계정 식별 정보 없이 임시로 읽어 같은 씬 update→서버 검증을 실행했고 통과했다. 제보와 같은 오류 진단 코드는 아직 확보하지 못했으므로 동일 원인 재현 완료로 간주하지 않는다. 임시 운영 스냅샷은 저장소에 포함하지 않는다.
- Chromium은 전투 진입·결과 UI를 그리되 전투 중에는 Phaser의 headlessStep으로 GPU 그리기 비용만 제외한다. 실제 시계·씬 update·서버 검증은 유지한다. 전체 기기·모든 편성의 브라우저 회귀는 아니다.

DB 스키마 변경이나 실제 계정·보상 수정은 없다. 배포 서버 생성물은 공용 소스에서 다시 생성한다.
