# 실시간 아레나와 친구 친선전 — v0.326.0

## 플레이 경로

- 로비 결투 → 기존 모드 선택 팝업 재사용 → 결투장 / 아레나. 두 칸 모두 현재 결투장 원화를 쓰며 아레나 칸에는 렉시아·스피나 SD와 전기 장식이 선다. 팝업 닫기·씬 종료 시 늦은 SD 로드도 폐기한다.
- 아레나 로비 → 독립 RP·티어·승패 카드 → 하단 매칭 → 별도 대기 씬(시간·SD 도약·취소) → 매칭 완료 시 밴픽/배치.
- 친구 프로필 → 친선전 → 결투장 방어덱 모의전투 / 아레나 실시간 요청. 모의전투는 현재 편성으로 친구가 저장한 방어덱과 싸우며 티켓·지갑·티어를 바꾸지 않는다.
- 실시간 친선 요청자는 밴 유무, 신청자 선공/후공/랜덤, 교차 공개/동시 비공개 배치를 선택한다. 상대에게 상단 수락/거절 배너가 뜬다. 전투 중·타이틀·계정 화면에서는 배너가 입력을 끼어들지 않는다.

## 규칙과 저장

- 랭크: 양측 각각 상대 렐릭 1밴, 선후공 랜덤, 한 명씩 교차 선택·자유 배치, 각 3명. 밴 때문에 양측 최소 보유 4명이 필요하다. 교차 선택은 자기 턴마다 렐릭과 위치를 함께 확정한다. 같은 렐릭을 양 팀이 각각 쓰는 것은 허용한다.
- 배치는 자기 진영 안 정규화 좌표다. 유한수·영역·최소 80px 간격·자기 보유·밴·중복 선택·현재 차례를 서버가 검증한다. 비공개는 자기 배치를 되돌릴 수 있고 각자 확정한 뒤 공개한다. 서버 응답도 공개 전 상대 선택을 지운다.
- 준비 턴은 45초, 요청은 60초, 큐 heartbeat는 5초/20초 유효다. 준비 시간 초과는 미완료 측 패배이며 비공개 양쪽 미완료는 무승부다. 기권은 패배다. 요청 거절/만료·중복 방 점유를 처리한다.
- 시작 시 서버가 양쪽 성장·유대·돌파·룬과 배치를 고정한다. 양쪽은 동일한 canonical 시점과 시드의 자동 전투를 본다. 내 팀이 상단/하단 중 어디인지 전장에 표시한다. 상대용으로 코어 순서나 시드를 뒤집지 않는다.
- 결과는 `settleArena`가 서버 코어로 재현한다. 클라이언트 승리 여부를 받지 않는다. RP·승패 두 계정을 DB 트랜잭션에서 한 번만 반영하며 기존 결투장 `Session.duel`과 지갑을 건드리지 않는다. 친선·모의전투는 RP도 변경하지 않는다.
- 첫 RP 1000, 티어 브론즈/실버1100/골드1300/플래티넘1500/다이아몬드1800/마스터2100. 시즌 초기화·시즌 보상·랭킹 보상은 이번 범위에 넣지 않았다.
- 서비스 롤 전용 방/큐/RP/영수증/점유 표와 CAS를 사용한다. 공개 Realtime 표는 `arena_signals`의 소유자 전용 변경 번호뿐이다. 받은 이벤트는 재조회만 깨우며 상태나 결과로 신뢰하지 않는다. 2초 준비 조회와 8초 요청 조회가 연결 손실을 보완한다.
- 큐는 비슷한 점수부터 시작해 대기 시간에 따라 범위를 넓힌다. 사람만 매칭하며 NPC 대체는 없다. 동시 접속자가 없다면 매칭 대기가 계속되는 것이 정상이다.
- 앱 모듈 순서 변경으로 드러난 `SettingsManager` ↔ `FakeServer` 초기화 순환도 수정했다. 알림 스케줄러를 실제 사용하는 시점에 조회한다.

## 검증

- `tests/unit/liveArena.test.ts`: 밴 순서·보유·금지·중복·간격·비공개/되돌리기·배치 확정·공유 시드 재현·시간 초과·기권.
- `tests/unit/settingsImportOrder.test.ts`: 설정 매니저를 먼저 import해도 공유 FakeServer를 생성할 수 있다.
- `npm run test:arena-db`: 전체 마이그레이션을 적용한 격리 PostgreSQL에서 실제 서버 어댑터/RPC를 사용한다. 두 실제 저장 계정의 랭크 매칭→밴→6회 교차 배치→서버 전투 정산, 중복 요청/결과 재전송, 비공개 보호, 친선 무점수, 방어덱 모의전투, 기존 저장 무변경, 서비스 RPC·방 비공개와 신호 RLS를 검증했다.
- QA·운영 Supabase에 `realtime_arena` 마이그레이션 적용. 각 6개 아레나 표의 RLS, 신호 표의 Realtime publication, 인증 클라이언트의 방 RPC 실행 불가를 재조회했다. 기존 사용자 상태는 변경하지 않았다.
- 최종 main 통합판: `npm test -- --testTimeout=30000 --maxWorkers=1 --no-file-parallelism` 381개 파일, 4,489개 통과·1개 기존 건너뜀. 타입 검사·서버 생성·일반/QA 빌드·빌드 격리·출시 고정값 검사 통과.
- Chromium 화면 검사: 선택 팝업의 렉시아·스피나 SD → 독립 티어 카드 → 매칭 시간/SD → 취소 복귀 통과. 밝은 배경의 문구 대비도 보강한 뒤 재확인했다.
- main 통합 뒤 Chromium 전투 검사: 실제 캔버스 1밴 → 세 번의 교차 자유 배치 → 공용 자동 전투 → 승리 결과 팝업 통과(1.6분). 제어된 HTTP 응답을 사용하며 SQL/서버 정산은 위 격리 DB가 별도로 검증한다.
- 아레나 문구는 기존 12개 언어 표에 포함했고 고정 용어·자리 표시·정적 콘텐츠/글꼴 규칙을 검사했다.

## 실제 환경 확인 범위

격리 DB는 실제 SQL 권한/트랜잭션과 전투 정산을 검증하고, 브라우저 화면 검사는 제어된 응답으로 새 입구·티어·매칭을 확인한다. 서로 다른 실제 기기 두 대의 네트워크 지연·백그라운드 복귀, 대규모 동시 매칭 부하는 별도 실측이 필요하다. 일반/QA 모두 같은 아레나 경로이며 기존 QA 치트 분리 규칙은 유지한다.

main 통합 시 기존 v0.325.0의 일일 돌림판·로그인/닉네임·스토리 난이도 변경을 보존했다. 아레나는 v0.326.0으로 배포한다.
