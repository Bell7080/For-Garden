# 보상·전투 저장 복구

저장 v50은 계정 상태와 처리 영수증(`serverJournal`)을 같은 저장 단위로 확정한다. 출석과 우편은 후보 상태를 먼저 계산하고 저장 성공 뒤에 공유 세션을 바꾼다. 저장이 실패하면 같은 요청 ID로 재시도할 수 있다.

가방 API는 아이템당 한 행에 총수량과 전체 만료 묶음을 반환한다. 화면에서만 묶음별 칸으로 나눈다. v49의 잘못된 전체 lots 복제 행은 알려진 형태에 한해 수량 증가 없이 복구한다.

출석·우편·레이드 입장/제출/정산·원정 노드/보스/최종 정산의 영수증은 재접속 후에도 복원한다. 재응답의 지갑·인벤토리는 현재 계정 값이며 최초 영수증의 지급 내역을 계정에 다시 더하지 않는다. 로컬 저장 용량 때문에 최근 256개 영수증과 활성 원정의 영수증을 보관한다. 운영 서버에서는 계정별 지속 저장과 요청 ID 고유 제약으로 대체해야 한다.

레이드 입장은 당시 편성·성장·룬·공유 HP를 함께 보존한다. 제출 유예는 입장 시각부터 전투 최대 논리 시간에 10분을 더한 시간이다. 레이드가 종료돼도 유효한 입장은 이 범위에서 제출할 수 있다. 중단한 판은 레이드 목록에서 `다시 하기`로 추가 비용 없이 처음부터 재실행한다. 전투 중간 프레임과 궁극기 입력을 이어 재생하는 기능은 포함하지 않는다. 미제출 판이 유예 안에 남으면 최종 레이드 정산을 먼저 받지 못한다.

원정 보스 제출은 보스에 도달한 런만 받으며, 보스 결과 영수증 없이 정상 완료 정산하지 않는다. 제출 뒤 앱이 종료되면 같은 요청 ID가 인양 보상을 다시 쌓지 않는다. 최종 정산 후 활성 런이 없어도 정산 영수증을 복원한다.

주간 순위 보상은 가장 오래된 `pendingRankReward`와 나머지 `pendingRankRewards`로 보관한다. 지난 주를 초기화하기 전에 해당 주의 기록을 큐에 추가한다. 각 주의 우편 ID를 수령 기록에 남겨 재접속 후에도 중복 지급하지 않는다.
