# 간헐 저장 오류·계정 전환 재점검 (v0.323.4)

## 확인하고 수정한 경로

- 기존 원격 API는 네트워크 예외만 자동 재전송했고, HTTP 503·504는 바로 실패했다. HTTP 408·5xx·저장 충돌과 잘린 성공 응답도 동일한 요청 키로 한 번 재전송한다. 전체 요청 제한 시간 35초와 규칙 거절은 유지한다.
- 동일 쓰기 호출이 겹치면 하나의 Promise를 공유한다. 성공한 요청이 재시도 키를 지운 뒤 다른 요청이 실패하는 경합을 제거한다. 완료 뒤 별도 조작은 새 키로 실행한다.
- 새 로그인 성공 시 이전 갱신을 무효화한다. 로그아웃 전 시작한 로그인과 토큰 조회가 늦게 완료되면 취소한다. 플랫폼 토큰 저장/삭제를 순서대로 실행해 늦은 저장이 로그아웃 삭제를 덮지 않게 한다.
- 이전 계정 RPC의 늦은 401은 현재 토큰을 지우지 않는다. 게임·친구·길드 연결은 토큰을 기다린 뒤에도 현재 연결인지 확인해 이전 연결이 새 토큰으로 요청하지 않는다. 계정 RPC에도 15초 제한을 적용한다.
- 로그아웃 삭제가 끝날 때까지 토큰 조회를 취소해, 그 사이 저장소의 옛 토큰을 다시 읽거나 새 게스트를 만드는 경로를 차단한다.

## 회귀 검사

- 디안 없는 도도·매디·스테라 / 엘라·마키·스테라 / 렉스·메트·토리카 편성으로 치즈케이크 1~8단계, 1·2·3배속, 세 난수 조합 216건의 실제 BattleScene 기록을 서버에서 재현한다.
- 치즈케이크 1·8단계의 저장 충돌 후 재시도, 동일 완료 요청 중복, 저장 직후 첫 응답 504를 결합한다. 자동 재전송은 확정 영수증을 회수하며 완료 저장은 한 번이고 재화·스테미나도 한 번만 반영된다.
- 로그인/갱신 응답 순서 역전, 로그인 대기 중 로그아웃, 토큰 저장 대기 중 로그아웃, 이전 계정 RPC의 늦은 401, 토큰 대기 중 연결 종료를 검사한다.
- 브라우저 검사는 디안 없는 편성의 전투 종료 후 첫 완료 응답만 504로 바꾸고, 다음 응답 200·보상 표시·던전 복귀와 설정 예외 후 입력 복구를 확인한다.
- 위 브라우저 장애 주입 검사는 통과했다. 격리 PostgreSQL 전체 마이그레이션과 실제 RPC를 이용한 콘텐츠 루프도 통과했으며, 레이드·원정의 응답 유실·재접속·동시성·중복 보상 방지를 포함한다.
- 보스 퇴장 복구 E2E는 자동 재시도 두 번 모두 실패한 뒤의 수동 재시도 경로를 계속 검사하도록 장애 주입 횟수를 조정한다.

## 적용 범위와 한계

최종 확인: `npm run typecheck`, `npm test -- --testTimeout=20000` (372개 파일, 4,413 통과·1 제외), `npm run build`, `npm run build:server`, `npm run test:build-isolation`, `npm run test:release-fixtures`, `npm run test:content-loops`, Chromium 치즈케이크 단일 흐름 검사를 통과했다. 전체 E2E는 실행하지 않았다.

- 일반/QA가 공유하는 클라이언트 처리 변경이다. SQL·저장 형식 변경과 운영 데이터 수정은 없다.
- 위 경합과 장애 복구는 재현 가능한 조건이다. 제보 당시의 오류 코드·전투 기록을 확보하지 못했으므로, 모든 간헐 오류가 이 원인이라고 단정하지 않는다. 전투 검증을 생략하거나 실패한 전투에 임의 보상을 지급하지 않는다.
