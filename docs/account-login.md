# 계정 로그인 — 게스트 · 아이디/비밀번호 · (추후) 소셜

한 계정 = Supabase Auth의 **유저 하나**. 서버 진행(`player_saves`·길드·친구)은 모두 그 유저 ID에 걸려 있으므로,
로그인 방법은 그 유저에게 **정체성을 더하는 일**이지 진행을 옮기는 일이 아니다.

| 방법 | 상태 | 동작 |
| --- | --- | --- |
| 게스트 | 구현됨 | 익명 가입(`is_anonymous`). 토큰이 이 기기에만 있어 기기를 바꾸면 잃는다. |
| 아이디/비밀번호 | 구현됨(v0.320.0) | 메일 인증 없음. 아이디 → 합성 주소 `<아이디>@id.forgarden.app` + 비밀번호. |
| 소셜(구글·애플) | 예정 | `linkIdentity`로 같은 유저에 더한다. 아이디 계정에도 구글을 더하고, 반대로 구글 계정에 아이디를 더할 수 있다. |

## 흐름

- **새로 시작(타이틀, 기기에 계정 없음)**: 「계정 로그인」 → 회원가입 탭 → `registerWithId` → 입장 흐름.
- **다른 기기에서 이어서**: 같은 창의 로그인 탭 → `signInWithId`(password grant) → 서버 진행을 그대로 받는다.
- **기존 게스트 연동(설정 → 계정 → 아이디로 연동)**: `registerWithId`가 게스트 토큰을 받아 `PUT /auth/v1/user {email, password}`로
  **같은 유저를 승격**하고 토큰을 새로 받는다(claim의 `is_anonymous`가 바뀐다). 진행 병합이 필요 없다.
- **로그아웃/계정 변경**: 토큰을 지우고 새 게스트를 만들지 않는다. 타이틀이 로그인 선택을 다시 보여 준다.
  게스트 계정에서 로그아웃하면 그 게스트는 되찾을 수 없다 — 먼저 아이디로 연동할 것.

## 규칙

- 아이디: 영문 소문자로 시작하는 4~20자 영문·숫자·`_`, 대소문자 무시. 비밀번호: 8~64자, 아이디와 달라야 한다(`core/accountCredentials.ts`).
- 비밀번호는 클라이언트가 보관·해시·로그하지 않는다. 입력 칸은 점으로만 그린다(`TextInputField`의 `mask`).
- 로그인 실패는 「아이디 또는 비밀번호가 올바르지 않습니다」 하나로만 말한다(계정 존재 여부를 흘리지 않음). 가입에서만 「이미 사용 중인 아이디」를 말한다.
- 메일이 없으므로 **비밀번호 복구는 없다.** 가입 창이 이를 한 줄로 알린다. 복구가 필요해지면 실제 이메일을 `linkIdentity`/`updateUser`로 더하는 흐름을 추가한다.
- 합성 도메인(`ACCOUNT_ID_DOMAIN`)은 기존 계정이 걸려 있으므로 바꾸지 않는다.

## 서버(Supabase) 설정 — 사람이 확인

DB 마이그레이션은 없다. Auth 설정만 필요하다(테스트 프로젝트에서 먼저 확인한 뒤 운영에 같은 값을 적용).

1. Authentication → Providers → **Email 켬**.
2. **Confirm email 끔** (켜 두면 가입 응답에 세션이 오지 않아 가입이 실패한다).
3. 최소 비밀번호 길이 8 이상, 가능하면 유출 비밀번호 검사 켬.
4. 익명 로그인은 기존대로 켠 상태 유지(게스트 승격에 필요).
5. 속도 제한: 로그인·가입 시도는 Auth의 기본 제한(429)을 쓰며 클라이언트는 「시도가 너무 많습니다」로 보여 준다.

## 추후 구글 양방향 연동 메모

- 구글로 시작한 계정에 아이디를 더하려면 `registerWithId`의 승격 분기를 `is_anonymous`가 아니라 "이메일이 합성 주소가 아님"까지 보도록 넓힌다
  (지금은 이미 연동된 계정이면 `alreadyLinked`로 거절).
- 아이디 계정에 구글을 더하려면 설정의 「Google 연동」이 `signInWithOAuth` 대신 `linkIdentity('google')`를 부르게 한다.
- 두 경우 모두 유저 ID가 같아 진행 병합이 없다. 이미 다른 유저가 쓰는 구글 계정이면 `identity_already_exists`로 거절된다.

## 로그인 방법 여러 개 (v0.321.0)

- 한 계정(유저 ID)에 아이디·Google·Apple을 함께 걸 수 있고, **언제나 하나 이상 남아야** 한다. 구글을 애플로 바꾸려면 애플을 더한 뒤 구글을 해제한다.
- 목록은 `GET /auth/v1/user`의 `identities`(`email`은 아이디 로그인), 연동은 `GET /auth/v1/user/identities/authorize`, 해제는 `DELETE /auth/v1/user/identities/{identity_id}`.
- Supabase 설정(운영 적용 전 사람이 확인): Authentication → Sign In / Providers → **Allow manual linking 켬**, Google·Apple 제공자 키 입력, Redirect URL에 서비스 주소 추가. 꺼져 있으면 [연동]은 「미지원」을 안내한다.
- 이메일 연동은 인증 메일이 필요해 이 단계에 넣지 않았다.
- 소셜 로그인으로 **다른 기기에서 들어오는** 길(타이틀의 Google/Apple)은 아직 자리표시자다.
