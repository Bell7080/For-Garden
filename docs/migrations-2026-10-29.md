## 검증

- QA의 임시 계정/길드 트랜잭션에서 이름 변경·같은 요청 재실행·일반 길드원 거절·중복 이름 거절·request ID 검증 통과. 1~10레벨 배치 순서가 열린 칸만 포함하고 중복이 없으며 우두머리 1/2/3지부로 시작하는 것을 확인했다.
- 당시 실제 시각은 전투일이었다. QA에서 방어덱 자동 배치·이동·재배치가 모두 `WAR_LOCKED`로 차단됨을 확인했다. 임시 표본은 롤백했다.
- 외부 네트워크 없는 임시 PostgreSQL 16 컨테이너에 저장소 전체 마이그레이션을 순서대로 적용했다. 해당 격리 DB의 최상단 RPC 시각만 정비일로 고정해 첫 빈 칸 자동 배치, 기존 칸 유지, 재요청, 길드원 권한 차단, 자리 교환, 간부 이동, 전투력순 재배치까지 실제 SQL로 통과했다. 컨테이너는 제거했다. 원격 함수의 시각은 바꾸지 않았다.
- 관련 Vitest 4파일·28개 통과.
- QA·운영의 최상단 RPC, 공격 래퍼, 순서 함수 정의 해시 일치. 이름 변경 래퍼는 과거 SQL 주석 유무만 달라 주석·공백 제외 본문 해시가 일치한다(`31bfc0318c1c14a34ac05b46617004e5`).
- 관련 네 함수는 빈 `search_path`, `anon`/`authenticated` 실행 불가, `service_role` 실행 가능을 유지한다. 보안 Advisor에서 이번 관련 함수의 새 안내는 없었다. 프로젝트 전체의 기존 보안 안내가 없다는 뜻은 아니다.
- 저장소 마이그레이션의 생성 대상 public 테이블 59개가 QA·운영 양쪽 모두 존재한다. 과거 이력은 도구가 기록한 날짜와 저장소 날짜가 달라 이름/스키마를 함께 비교했고, 이미 반영된 과거 파일은 재실행하지 않았다.

검증 SQL과 격리 실행기는 `docs/qa/guild-migrations-2026-10-29/`에 남겼다. 운영 계정·재화·기존 방어진을 초기화하거나 보상 소급 지급을 하지 않았다. DB 적용 당시에는 앱 코드 수정·커밋·푸시·재배포를 하지 않았다.

## 후속 적용 — 클라이언트 오류 수집 (v0.393.0)

메인 `55297e0e`를 fast-forward로 받아 `20261116000000_client_errors.sql` 누락을 확인했다. 원본을 수정하지 않고 QA 검증 후 같은 SQL을 운영에 적용했다.

- SHA-256: `ee6590d6586289f19634fca73d211e2fade644cf4248e200802d33c3fe313ac3`
- QA: `20261029131539_client_errors`
- 운영: `20261029131655_client_errors`

`client_errors` 표·인덱스·직원 조회 정책과 오류 보고/상태 변경/중복 판정 함수를 추가한다. 기존 계정·저장·재화는 바꾸지 않는다. 출시 초기화 스크립트의 해당 표 분류도 메인에 포함되어 있으나 실제 초기화는 실행하지 않았다.

QA에서 롤백하는 임시 계정·운영자 트랜잭션으로 미인증 보고 거절, 잘못된 종류 거절, 같은 오류 중복 집계·발생 횟수, 일반 사용자 RLS 조회 차단·상태 변경 거절, 운영자 조회·상태 변경, 같은 버전의 fixed 유지·새 버전 재발 시 open 전환, 필드 길이·맥락 크기 제한, 계정당 시간당 30건 후 거절을 검증했다. 관련 Vitest 2파일·8개도 통과했다. SQL은 `docs/qa/client-errors-migration-2026-10-29/verify.sql`에 남겼다.

운영·QA의 세 함수 정의 해시와 RLS/정책이 일치하고, 마이그레이션 이력이 기록됐으며 검증 표본 잔존 행은 0개다. 익명 역할에는 RPC 실행 권한이 없고 로그인 역할은 보고 RPC를 실행할 수 있다. 관리자 상태 변경 RPC도 로그인 역할에 노출되지만 내부 `private.admin_can(owner/operator)` 검증으로 일반 계정을 거절한다. 해당 SECURITY DEFINER RPC 두 개에 대한 Advisor 안내는 이 설계 때문에 표시되며 일반 사용자 거절을 실제로 검증했다. 익명 게스트 가입 계정은 미인증 요청과 다르게 authenticated 역할을 받는 기존 로그인 정책을 따른다.

이 후속 DB 적용 당시에도 앱 코드 수정·커밋·푸시·재배포는 하지 않았다. 적용 기록과 검증 SQL은 이후 사용자의 공유 요청에 따라 v0.393.1에 포함한다.

환경/연결 중단이 반복되어 원격 QA 표본 검증의 완료 결과는 회수하지 못했다. 같은 호출을 반복하는 대신 격리 DB 검증과 QA의 읽기 검증으로 확인 범위를 구분했다. 운영 적용 시에는 QA 이력에 보관된 SQL의 SHA-256이 원본과 정확히 같은 것을 확인한 뒤 그대로 적용했다. 이미 적용된 QA SQL은 재실행하지 않았다.

- 관련 Vitest 4파일·36개 통과.
- 외부 네트워크 없는 격리 PostgreSQL에 전체 마이그레이션을 적용하고, 그 DB 안에서만 정비일 판정을 고정해 실제 SQL 검증 통과. 대기 덱 검증·동기화, 전투력순 배치, 중복 방지, 47시간 제외·48시간 복귀, 간부 제거·지도 재채우기 방지, 본인 직접 배치 시 제외 해제, 기존 칸 유지, 매칭 직전 채우기를 확인했다. 컨테이너는 제거했다.

후속 기록 공유(v0.394.1)에서 두 환경의 적용 이력·원본 SQL 해시·함수 해시·클라이언트 역할 차단을 다시 읽어 일치함을 확인했다. DB 마이그레이션을 추가 실행하지 않았다.
