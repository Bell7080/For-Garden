# 스토리 난이도·보상·정예 일치 (v0.326.3)

쉬움 관문을 유일한 원본으로 삼는다. 보통/어려움은 ID와 선행 조건·보상만 난이도별로 만들고 적 ID·레벨·돌파·자리·개체별 정예는 원본을 복사한다. 난이도 종족값은 `STORY_DIFFICULTY.statFactor`의 보통 1.4 / 어려움 2.0이며 체력·공격·주문·방어·저항에만 적용한다. 태생 단계(테러조 1.0 / 회수조 1.3), 정예의 체력 몫, 캐릭터 스킬은 기존 규칙을 유지한다. 별도 레벨 사다리와 미리보기의 배율 문구는 제거했다.

| 전환 | 이전 4-10 | 다음 1-1 |
| --- | ---: | ---: |
| 쉬움 → 보통 | 9,700 | 8,812 |
| 보통 → 어려움 | 12,961 | 11,653 |

표는 표시 전투력 검수이며 서로 다른 편성·스킬·머릿수의 실제 승률을 동일하게 만든다는 뜻은 아니다. 보통/어려움 1-1 표시 레벨은 쉬움과 같은 `[5, 5, 5]`, 4-10은 `[56, 35]`다. 어려움 4-10 전투력은 17,856이다. 쉬움의 레벨/정예/편성을 수정해 빌드하면 다른 난이도에도 반영된다.

골드는 원본 초회 표를 1/10로 줄이고 난이도 적용 후 100 단위로 반올림한다. 젬은 난이도 적용 후 10 단위로 반올림한다. 예: 보통 1-1 젬 40, 보통 4-6 골드 4,800/젬 60. 초회 치즈케이크·원석·화석·룬의 용도와 기존 클리어/수령 기록은 보존한다. 보통/어려움 추가 재화 배율은 기존 1.25/1.5다.

4-6·4-9는 관문 전체가 정예가 아니라 코마 한 명만 정예다. 기존 능력치는 정예로 계산됐으나 지도와 편성은 `stage.elite`, 전투 크기는 팀 공통 배율만 읽어 딱지·크기가 빠졌다. 지도·편성은 개체 `encounterRole`을 우선하고 전투는 `enemyBodyScales` 배열을 서버 발급/저장/재현까지 넘긴다. 코마만 1.18배이며 양옆 적은 1배다. 3-5·3-10 및 4장 정예 둘 편성도 같은 규칙으로 검증한다. 기존 진행 중 전투 lease는 원래 저장된 옵션을 유지한다.

검증 항목: 모든 난이도의 원본 레벨/돌파/편성/정예 동등성, 오각형 보정과 부가 능력치 불변, 전환부 전투력, 젬 단위와 골드 규모, 서버 실제 지급 영수증, 3·4장 정예의 전투 발급·SaveManager 저장 왕복·코어 복원·편성 역할 일치. 모바일 브라우저 한 편에서 혼합 정예 딱지와 3장 단일 정예 화면을 확인한다.

실전 검수는 레벨 60·돌파 상한·실제 `generateRune → enhanceRune → applyHeartGems` 경로의 전설 룬 3개(옵션별 2성공/1실패), 서버와 같은 개체별 크기로 5개 파티×5개 관문×3시드를 비교한다. 보통 최종은 15/15승, 어려움 최종은 토리카/렉시아/루카 3/3승·노도니아/스피나/메테 1/3승이며 다른 3개 기준 파티는 패배했다. 1.6/2.6배로 전환부 표시 전투력만 정확히 맞췄을 때는 실제 장비 기준 최종 어려움이 모두 패배해, 최종값은 1.4/2.0배로 낮추고 전환부 약 10% 차이를 허용했다. 표시 전투력 자체를 전투 판정에 사용하지는 않는다.

최종 검증: Vitest 381개 파일, 4,507개 통과·1개 기존 건너뜀. Pixel 7 소스 브라우저의 혼합 편성/3장 정예/지도 표시 한 편 통과(1.5분), 지도 SD 셋 모두 로드된 뒤 캡처했다. 타입 검사·생성 서버·일반/QA 빌드·실제 두 빌드의 저장/디버그 격리·출시 고정값 검사도 통과했다.
