# Supabase 연동 안내와 남은 작업

초기 연동 단계표와 wallets 등 가상 테이블 초안은 현재 구현으로 대체됐다. 새 경계를 추가할 때는 다음 문서와 코드가 기준이다.

- [실서버 계약](server-release.md): 인증·저장 revision·멱등·친구·공유 레이드·전투 검증.
- [서버 전환의 남은 요구](server-migration.md): 아직 닫지 않은 경계와 출시 전 확인.
- [계정 로그인·연동](account-login.md): 서버 가입·아이디 별칭·PKCE·동일 UID 연동·약관·탈퇴.
- [DB 적용 이력](../supabase/README.md#적용-이력): QA/운영 원격 버전, 원본 해시와 실제 함수 검증.
- [출시 차단 항목](release-fixture-cleanup.md), [출시 초기화](launch-reset.md).

게임 규칙은 `src/core`, 정적 정의는 `src/data`, API 계약은 `src/api/contracts.ts`, 실제 요청 처리는 `src/server`가 소유한다. 실제 지갑은 서버 저장의 `wallet`이며 초기 계획의 별도 wallets 테이블을 새로 만들지 않는다. 서버 호출은 인증된 UID, 서버 소유 난수·시각·전투 재현, revision·request ID 경계를 유지한다.

QA와 운영 프로젝트·저장은 분리한다. 새로운 서버 기능은 QA에서 마이그레이션과 계약을 검증한 뒤 같은 원본을 운영에 적용한다. 이력 이름만 보고 이미 적용된 파일을 재실행하지 않는다.

남은 출시 확인은 실기기 보안 저장소·웹 토큰 임시 예외 제거, 실제 스토어/광고 검증기, Google/Apple·SMTP 제공자 설정, 계정 삭제 스케줄 운영을 포함한다. 코드 구현과 DB 함수 생성만으로 제공자 설정·스케줄 실행까지 완료된 것으로 취급하지 않는다. 상세 미완료 항목은 위 운영 문서에서 관리하며 이 문서에 옛 단계별 실행 기록을 복제하지 않는다.
