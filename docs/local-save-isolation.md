# 로컬 저장·디버그 분리 (v0.290.0)

## 작업 범위와 협업 경계

최초 대조 main `05e6ee2b` / v0.288.1에는 이미 `startupGate`와 서버 시계가 연결되어 있고, 게스트 계정·클라우드 저장 어댑터 기반도 있다. 초기 감사(v0.286.0)의 "시작 관문 미호출"은 이제 지난 상태다. 최종 반영 전에 추가된 main `063e1a2d` / v0.289.0의 서버 상태 실행·`RemoteGameApi`·`SaveManager.parse`도 보존해 병합했다. 서버 생성물은 새 공용 모듈에 맞게 재빌드한다. 이번 변경은 클로드의 Supabase 이전과 독립된 클라이언트 저장·진단 경계만 다룬다. `src/api/*`, 원격 DTO·SQL·DB·계정/지갑/우편/쿠폰 지급 규칙은 수정하지 않았다.

## 저장 키와 기존 진행

| 실행 | 활성 저장 키 |
| --- | --- |
| 일반 production 빌드 | `eternal-city.production.local-save` |
| QA 빌드·개발 서버 | `eternal-city.qa.local-save` |
| E2E `--mode test` | `eternal-city.test.local-save` |
| 이전 공용 기록 — 읽기·쓰기·삭제하지 않음 | `eternal-city.local-save` |

`src/core/saveStorage.ts`가 키와 현재 빌드 출처를 정의한다. `SaveManager`는 선택한 키에서만 load/save/reset한다. URL 옵션은 저장 공간을 바꾸지 않는다. 테스트용 생성자 두 번째 인자는 브라우저 입력으로 노출되지 않는다.

**일반·QA·E2E 모두 이번 업데이트 후 새 로컬 공간으로 시작한다.** 이전 공용 기록은 출처 정보가 없어 재화량·캐릭터 수·아이템을 보고 QA로 판정할 수 없다. 자동으로 가져오면 QA 지급을 운영 진행으로 다시 수입하므로 자동 이관하지 않는다. 원래 문자열은 구형 키에 그대로 남겨 삭제 없이 보존한다. 새 모드의 초기화와 손상 복구도 구형 기록이나 다른 모드 기록을 지우지 않는다.

구형 정상 진행을 복원해야 한다면 먼저 브라우저 저장소에서 구형 키의 원문을 별도로 보관하고, 출처·계정·지급 내역을 확인한 명시적 이관 절차를 사용해야 한다. 원문을 운영 키에 무조건 복사하는 자동 마이그레이션을 추가하지 않는다. 현재 이번 변경에 이관 UI나 구형 데이터의 진위 판정 기능은 포함되지 않는다.

`SaveData` 형식(v50)과 `exportData`/`importRemote` 계약은 유지한다. 따라서 **로컬 키 분리는 보안 검증이나 원격 QA 데이터 수입 방지 기능이 아니다.** 다음 서버 이전에서 운영·테스트 Supabase 프로젝트/인증/저장을 실제로 분리하고, 클라이언트 스냅샷을 서버 지갑의 권위 있는 근거로 받아들이지 않아야 한다. 예전 원격 저장 자체가 QA에서 만들어졌다면 별도의 서버 이관 정책이 필요하다.

## 디버그 경계

모든 `src/debug.ts` 관측 함수는 일반 빌드에서 상태를 만들기 전에 종료한다. perf 쿼리도 QA/test/dev에서만 처리한다. 렌더당 관측 복사, 전역 `__PF_DEBUG`, 오버레이 DOM, Puppet 시간 측정과 진단용 WebGL 이벤트 구독이 일반 게임에 남지 않도록 한다. 실제 Phaser의 context 복귀 기능을 제거한 변경은 아니다.

QA와 E2E는 기존 씬·팝업·좌표·지갑 관측 계약을 유지한다. 이 디버그 값은 검증용 관측값이며 서버가 신뢰할 상태나 인증 정보가 아니다.

## 확인 방법과 후속 담당

- Vitest: 같은 Storage에서 3개 모드 왕복·구형 공용 기록 무시/보존·손상 QA 복구의 다른 모드 영향·SaveData 원격 호환을 검증한다. MODE/DEV 조합과 일반 모드에서 모든 관측 함수가 DOM·전역을 만들지 않는지도 확인한다.
- production/qa/test 별도 빌드 산출물에서 debug/perf 코드와 선택된 저장 키를 대조한다. 일반 `?perf=1`은 계측을 켜지 않아야 한다.
- `npm run build` 뒤 `npm run test:build-isolation`로 실제 소스의 production/qa/test 컴파일·저장 왕복·일반 번들의 관측 코드 제거를 다시 검증한다. QA/test 산출물도 검사하려면 `node scripts/check-build-isolation.mjs dist <qa-dist> <test-dist>`를 사용한다. 이 검증은 DB나 서버를 호출하지 않는다.
- E2E 준비 헬퍼는 명시적 test 키를 사용한다. 화면 배치는 바꾸지 않았으며 전체 E2E는 실행하지 않는다.
- **이번에 맡은 범위:** 저장 namespace·관측 경계·회귀 검증.
- **클로드와 함께 남은 범위:** 운영/테스트 Supabase 프로젝트와 원격 저장 분리, 구형 실제 진행의 검증된 이관, 계정/지갑·수령 계약, 미완성 메뉴와 모의 소셜/랭킹의 출시 노출 정책. 초기 감사의 미해결 항목을 완료로 바꾸지 않는다.

## 이번 실행 결과

- 최종 병합 상태의 전체 Vitest: 310개 파일, 3,675개 통과·1개 건너뜀. 새 서버 처리기·원격 API 테스트도 포함한다.
- typecheck, 서버 생성물 재빌드, 최종 production Vite 빌드 성공. QA/test Vite 산출물 및 실제 소스의 세 모드 저장 왕복·관측 코드 포함 여부 검증도 통과했다.
- 일반 번들에 `__PF_DEBUG`, `pf-perf`, `puppetUpdates` 문자열이 없음을 확인했다. QA/test에서는 관측 계약을 유지한다.
- 전체 E2E와 운영 DB 요청은 실행하지 않았다.
