# For - Garden

> 이터널 시티 — 멸종 동물 복원 연구 도시

세로형 모바일 수집형 RPG. 멸종한 DNA를 되살린 호문쿨루스 소녀 **RELIC**들이 사는
**이터널 시티**에 유일한 연구원(주인공)이 입주하며 그들을 관리해 나가는 이야기.

소녀전선 스타일의 코어 컨텐츠, 니케 스타일의 세로형 화면, 림버스 컴퍼니 같은 인디 감성을
목표로 한다. 1인 개발로 감당 가능한 범위를 우선한다.

- 세계관 전문: [`docs/lore.md`](docs/lore.md)
- 수집형 RPG로서 비어 있는 축: [`docs/design-gaps.md`](docs/design-gaps.md)

## 현재 상태

코어 전투 루프와 메인 화면의 첫 형태가 돈다.

`타이틀 → 로비 → (출격) → 스테이지 지도 → 파티 편성 → 전투 → 결과`

하단에 탭 세 개가 늘 떠 있다.

- **렐릭**: 보유한 렐릭을 훑어본다. 아직 없는 렐릭도 `???`로 자리를 남겨 둔다.
  하나를 고르면 상세 정보를 보거나 로비에 세울 **애착 렐릭**으로 지정할 수 있다.
- **로비**: 메인 화면. 광장에 애착 렐릭이 서 있고 그 위에 출격 버튼이 얹힌다.
  상점 · 우편 · 프로필 자리를 잡아 뒀다(아직 눌러도 준비 중이다).
- **연구소**: 화석(흔한 재화)과 호박석(귀한 재화)으로 렐릭을 발굴한다. 1회 · 10회 뽑기가
  있고 10회가 낱개보다 싸다. 뽑기 규칙은 `src/core/gacha.ts`에 순수 함수로 있고 난수를
  밖에서 받는다 — 나중에 서버가 결과를 정하게 되어도 계산식을 그대로 쓸 수 있다.
  현재는 `GameApi` 인터페이스와 비동기 `FakeServer`가 재화 검사·차감·난수 결과를 한곳에서
  확정하며, 실제 서버가 준비되면 API 구현체만 HTTP 통신으로 교체할 수 있다.

- **스테이지 지도**: 세로 게임이므로 진행 경로가 아래에서 위로 뻗는다. 1-1부터 1-5까지 있고,
  직전 스테이지를 깨야 다음이 열린다.
- **파티 편성**: 위쪽에 이번 전투의 전장을 그대로 축소해 보여준다. 적 진형에서 누가 선봉인지
  들어가기 전에 눌러 확인할 수 있고, 내가 고른 렐릭이 어느 자리에 서는지도 함께 보인다.
  아래쪽 보유 렐릭 그리드는 짧게 누르면 편성, **꾹 누르면 상세 정보**다.
- **전투**: 적은 우상단, 아군은 좌하단에 각각 삼각형으로 서서 비스듬히 대치한다. 전방에 선
  쪽이 상대를 향해 튀어나온 꼭짓점이다.

### 임시 아트

PuppetForge로 만든 묶음 둘을 돌려 쓰고 있다.

- `public/puppets/char_001.zip` — 정보창과 로비에 서는 전신 일러스트 (idle)
- `public/puppets/entity_001.zip` — 전장에 서는 SD 개체 (idle · hit · attack)

렐릭마다 제 그림이 없어서 아군도 적도 같은 개체를 세우고 **색 필터로만** 구분한다
(`src/puppets/tints.ts`). 전신 일러스트는 색을 진하게 씌우면 얼굴이 뭉개져 흰색 쪽으로 옅게 섞는다.

발끝을 바닥에 맞추는 일은 `src/puppets/assets.ts`가 맡는다. PuppetCreature는 Phaser Mesh라
원점이 이미지 한가운데인데 이미지에는 투명한 여백이 넓게 붙어 있어서, 좌표를 그대로 넣으면
캐릭터가 공중에 뜬다. 그림이 실제로 있는 영역을 미리 재어 두고 발끝과 가로 중앙을 맞춰 놓는다.

### 전투 화면 조작

- **좌하단 리볼버**: 교대할 렐릭 3명이 원형으로 서 있고 맨 위가 출전 중이다. 아래 두 명 중
  하나를 누르면 실린더가 돌 듯 자리를 바꿔 선봉으로 올라온다.
- **우측**: 위에서부터 적 정보 · 궁극기 · 기본 공격.
- **`?` 아이콘**: 렐릭과 스킬 위에 붙어 있다. 누르면 정보창이나 스킬 툴팁이 열린다.

정보창은 `src/managers/CharacterInfoManager.ts`를 공개 진입점으로 쓰고,
`src/ui/info.ts`의 공용 프리팹이 실제 배치를 전담한다. 아군이든 적이든, 편성 화면이든 전투
중이든 **능력치 · 패시브 · 기본 공격 · 궁극기**를 언제나 같은 순서로 낸다. 화면마다
정보 형식이 갈라지지 않게 하려는 것이다.

### 전투 규칙

턴제로 주고받는다. 한 턴에 아래 셋 중 하나를 고른다.

| 행동 | 설명 |
| --- | --- |
| 기본 공격 | 선봉이 적 선봉을 친다. 궁극기 게이지가 찬다. |
| 궁극기 | 게이지가 다 차야 쓸 수 있는 강한 공격. |
| 교대 | 후방과 선봉을 맞바꾼다. |

교대도 한 턴을 쓰고, 게다가 **교대한 다음 턴에는 다시 교대할 수 없다**. "강한 공격은 탱커로
막고 때릴 때 교대한다"는 판단에 대가를 붙이기 위해서다. 선봉이 쓰러지면 후방이 자동으로 앞에 선다.

서포트 스킬은 없다. 후방 2명은 **패시브로만** 전투에 관여한다. 엔진이 해석하는 패시브는 세
종류다 — 전방에서 받는 피해를 줄이는 `frontGuard`, 교대 직후 첫 공격을 강화하는
`swapMomentum`, 후방에 있는 동안 매 턴 선봉을 회복시키는 `rearMend`.

전투 엔진(`src/core/battle.ts`)은 난수를 쓰지 않는다. 같은 입력이면 같은 결과가 나와서
규칙을 테스트로 고정할 수 있다.

## 기술 스택

- Phaser 3 + TypeScript + Vite
- 기준 해상도 1080×1920 (9:16), `Phaser.Scale.FIT`으로 축소·중앙 정렬
  - 데스크톱의 넓은 창: 좌우 레터박스로 세로 화면이 그대로 축소되어 보인다 (컴퓨터 테스트용)
  - 모바일 기기가 실제로 가로로 눕혀졌을 때만 회전 안내 오버레이가 뜬다
    (`pointer: coarse` + `orientation: landscape` 조합으로 감지, `src/style.css`)
- 입력은 Phaser의 `pointerdown`/`pointerup` 추상화를 사용한다. 모바일에서는
  `touchstart`/`touchend`, PC에서는 마우스로 동작하므로 모바일 우선 반응과 개발 편의성을 함께 유지한다.
- [PuppetForge (WebGLE)](https://github.com/Bell7080/WebGLE)를 `puppetforge` 패키지로
  git 의존성 설치 — 이후 캐릭터 스탠딩/전투용 종이인형 애니메이션을 여기서 가져다 쓴다.
  설치 시 `prepare` 스크립트가 자동으로 `dist-lib`를 빌드하므로 별도 설정이 필요 없다.

## 스크립트

```bash
npm install       # puppetforge git 의존성도 함께 빌드된다
npm run dev        # 로컬 개발 서버 (컴퓨터 브라우저로 세로 화면 확인)
npm run build      # tsc --noEmit + vite build
npm test           # Vitest (코어 로직)
npm run typecheck
npm run test:e2e   # Playwright — 모바일 화면비/터치로 빌드 결과 구동 확인 (build 이후 실행)
```

## 구동 확인

CI는 두지 않는다. 배포는 Vercel이 맡고, 품질 게이트는 커밋 전에 로컬에서 직접 돌린다.

```bash
npm run typecheck && npm test && npm run build
npm run test:e2e   # iPhone 14 / Pixel 7 화면비로 빌드 결과를 실제로 띄워 본다
```

e2e는 캔버스가 세로로 렌더링되는지, 탭(터치)으로 씬이 전환되는지, 기기를 가로로 눕히면
회전 안내가 뜨는지를 확인하고 `test-results/`에 스크린샷을 남긴다. 실제 모바일 기기가 없을
때는 그 스크린샷으로 화면을 확인하면 된다.

## 배포 (Vercel)

배포는 **Vercel의 GitHub 연동**이 전담한다. `vercel.json`에 빌드 설정을
미리 넣어뒀지만, Vercel 쪽 저장소 연결(Import)은 계정 인증이 필요해 아래 절차를
Vercel 대시보드에서 직접 한 번 해야 한다.

1. https://vercel.com/new 에서 GitHub 계정으로 로그인 → `Bell7080/For-Garden` Import
2. Framework Preset은 Vite로 자동 인식됨 (`vercel.json`이 있으면 그대로 따른다)
3. 이후로는 `main`에 push할 때마다 Vercel이 자체적으로 빌드·배포한다 (PR에는 미리보기
   배포 URL이 자동으로 달린다).

빌드가 깨진 채로 push하면 Vercel 배포가 그대로 실패한다. 막아 줄 CI가 없으니 위의 품질
게이트는 반드시 커밋 전에 돌린다.

## 구조

```text
src/
  api/        # 서버 통신 규격(GameApi)과 백엔드 전까지 사용할 비동기 FakeServer
  config/     # 기준 해상도 등 상수
  core/       # 전투 · 뽑기 규칙과 타입. Phaser를 전혀 모른다 (Vitest 대상)
  data/       # 렐릭 · 스테이지 · 배너 정의. 밸런스는 코드가 아니라 여기서 만진다
  state/      # 씬 사이를 오가는 진행 상태 (보유 렐릭 · 재화 · 애착 렐릭)
  managers/   # 수집 상태 규칙 · 여러 화면에서 재사용하는 캐릭터 정보창 진입점
  puppets/    # PuppetForge 묶음 불러오기와 바닥 맞춤, 임시 색 필터
  scenes/     # Phaser 씬 (그리기와 입력만)
  ui/         # 버튼 · 이름표 · 리볼버 · 하단 탭 · 정보창 매니저 · 색과 글꼴 토큰
  debug.ts    # E2E가 씬 전환과 전투 상태를 확인하기 위한 window 훅
tests/
  unit/       # Vitest — 전투 규칙
  e2e/        # Playwright — 모바일 화면비 + 화면 흐름
```

의존 방향은 `scenes → core`, `scenes → data` 한 방향이다. `core`는 렌더러를 모른다.

수집 상태 변경은 `RelicCollectionManager`를 통해 검증한다. 캐릭터 정보창은
`CharacterInfoManager`를 통해 열기 때문에 전투·편성·도감 탭이 레이아웃을 각자 복제하지 않는다.

### 애니메이션 재생 안정화

Puppet ZIP 다운로드·파싱은 첫 캐릭터가 나타나는 프레임이 아니라 `BootScene`에서 미리 끝내고
공용 캐시에 보관한다. 일회성 공격/피격 모션은 개체별 최신 동작 번호를 사용하므로 이전 동작의
idle 복귀 타이머가 새 동작을 중간에 끊지 않는다. Phaser는 60fps를 목표로 프레임 간격을
평활화하고 WebGL이 가능한 브라우저에서는 GPU 렌더링을 사용한다.
