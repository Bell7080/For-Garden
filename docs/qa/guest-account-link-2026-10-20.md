# 게스트 계정 연동 점검 — v0.320.9

## 재현과 수정

`SupabaseAccountApi.isAnonymous`가 이메일의 존재를 문자열 타입만으로 판단했다. 실제 익명 JWT의 `is_anonymous: true, email: ""`도 연동된 password 계정으로 표시했다. 이 때문에 `SettingsScene.buildSupportRows`는 연동 버튼 대신 로그아웃만 표시했고 `registerWithId`도 `alreadyLinked`로 거절했다.

명시된 `is_anonymous` boolean을 우선한다. 이 필드가 없는 구형 토큰은 비어 있지 않은 이메일이 있을 때만 연동된 계정으로 분류한다. 신규 계정 생성, 저장 데이터 삭제/병합/이관, SQL 변경은 없다. 게스트 승격은 기존 `PUT /auth/v1/user`와 토큰 갱신 경로를 그대로 쓴다.

## 검사 범위

- 수정 전: 신규 회귀 검사 중 5개 실패로 오분류 재현.
- 수정 후: 계정 어댑터 검사 21개 통과. 저장된 게스트 복원, 만료 토큰 갱신, 동일 UID 아이디 승격, 인증 저장소에서 새 어댑터를 만들어도 같은 연동 계정 복원, 비익명 계정 재등록 거절 확인.
- 전체 단위 검사: 353파일, 4,085개 통과 / 1개 건너뜀. 타입 검사, 정식 클라이언트 빌드와 서버 생성 빌드 통과. 기존 큰 청크 경고는 남아 있다.
- HTTP 응답을 주입한 계약 검사다. 운영 Supabase의 실제 가입/승격과 기기 간 로그인은 이 환경에 관리 권한이 없어 실행하지 않았다.

## 현재 main에서 남은 인증 기능

- `SupabaseAccountApi.login`: 구글·애플은 실제 OAuth 구현 없이 `unsupported`를 반환한다.
- 이메일 인증·복수 identity 목록·추가 연동·연동 해제 계약/화면은 없다. 단순히 메뉴를 표시하는 것만으로 지원되지 않는다.
- 추가 구현 시 로그인에 의한 계정 교체와 **동일 UID에 identity를 추가하는 연동**을 구분해야 한다. 기존 제공자 계정에 진행이 있으면 자동 덮어쓰기/병합하지 않는다.
- Supabase 제공자 설정 및 Google/Apple OAuth 자격 증명·허용 redirect, 수동 identity linking 설정과 콜백 처리가 필요하다. 이메일은 인증 완료 전후 상태를 다뤄야 한다. 마지막 로그인 수단 해제는 막고 서버의 재인증/해제 제약을 따른다.
- 기존 웹 게스트 토큰 임시 저장 예외를 소셜 토큰으로 확대하지 않는다. 토큰 보관은 보안 플랫폼/서버 세션 경계를 먼저 마련한다(`CLAUDE.md`, `docs/release-fixture-cleanup.md`).

배포 후 기존 게스트에서 설정의 지원·데이터 탭 → 아이디 연동을 확인한다. 연동 전후 UID·보유 렐릭·재화·관문 기록이 같고, 다른 기기에서 해당 아이디로 로그인해 같은 서버 진행을 읽는지 확인한다. 수정 확인을 위해 게스트를 로그아웃하거나 사이트 데이터를 지우지 않는다.
