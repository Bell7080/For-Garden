# 레이드·원정 전투와 정산 기준

신규 UI 입장은 `replayVersion: 2`를 사용한다. 레이드는 입장 영수증 ID, 원정은 `[runId, nodeId]`에서 동일 난수열을 만들고 20ms씩 진행한다. 배속과 렌더 프레임은 누적 시간을 틱으로 나눌 뿐 결과 계산에 들어가지 않는다. 궁극기는 틱 사이에 실제 시전한 순서대로 기록하며 정산은 동일한 생존·게이지·상태 조건을 검사한다. 자동 평타·소환수·보스 AI는 조작 로그가 아닌 같은 코어가 재현한다. 클라이언트의 피해 숫자는 제출하지 않는다.

레이드는 모든 피해 원천이 지나는 HP 변경 경계에서 점수를 센다. 방어/속성/받는 피해 경감/보호막/무효화와 죽음 방지가 적용된 실제 HP 손실이다. 과잉 타격은 남은 HP까지만 인정한다. 입장 이후의 개인 전투는 입장 시 남은 HP를 사용하며 전투 HUD도 같은 값을 그린다. 정산의 `runDamage`는 이 개인 기록, `sharedDamage`는 제출 시 실제 공유 HP 차감량이다. 다른 참가자가 먼저 처치했어도 유효한 입장의 개인 기록·골드는 유지하고, 공유 HP는 0 아래로 내려가지 않는다. 누적 개인 기록은 `myDamage`, 공유 차감은 `appliedDamage`로 저장한다. 이전 저장은 `appliedDamage ?? myDamage`로 해석한다.

원정 폰토스는 경감 전 화력 점수 규칙을 유지한다. 점수는 `expeditionBossDamageScore(round(boss.score))`로 환산한 뒤 일반 노드 점수를 더하며 전투 HUD/최종 결과/주간 최고점에 같은 식을 사용한다. `verifiedDamage`는 기여도 창이 표시할 실제 HP 피해다. 환산 점수를 피해량 합계로 쓰지 않는다. 출혈 등 최대 HP 비례 피해는 공유 HP가 아닌 보스 성장 기준을 사용한다.

레이드·원정 보상은 지갑 상한 이후 실제 증가분만 지급 결과에 담는다. 지급, 처리 ID, 점수/진행 상태는 하나의 저장에서 확정한다. 저장 실패는 입장/런을 보존하며 재시도한다. 같은 처리 ID의 재접속 응답은 원래 보상 영수증과 현재 지갑을 반환하고 지급을 반복하지 않는다. 레이드 순위 목록도 복구한다. 원정 소탕과 최고점 보상에 같은 규칙을 적용한다.

`bodyHp`와 `kills`는 전체 HP를 산정하는 밸런스 단위/배수이며 실제 처치·부활 횟수가 아니다. 전투는 단일 공유 HP 풀이다. 시간 단계는 표시 구간이며 난이도는 보스 성장·돌파·기술과 공용 데스 카운트가 결정한다.

## 운영 서버 경계

현재 `gameApi`는 로컬 `FakeServer`이며 QA의 다른 참가자 피해는 모의 곡선이다. 이 구현은 여러 계정이 실제로 공유하는 서버/DB가 아니다. 외부 서비스를 설정하거나 배포하지 않았다. 운영 협동 레이드에는 기존 `GameApi` 계약을 구현하는 인증 서버와 공유 raid 레코드가 필요하다. 입장 스냅샷·개인 기여·공유 HP 차감·영수증·보상은 서버 DB 트랜잭션으로 함께 확정해야 하며 모의 곡선을 운영 참가자 기록으로 사용하면 안 된다. 이번 수정은 그 계약과 공용 전투 코어를 정리한 것이다.

## 회귀 검증

- `bossSimulationConsistency.test.ts`: 여러 편성/보스, 자동·수동 궁극기, 프레임 지연, 1/3배속에서 점수·종료·생존 일치 및 방어/보호막/무효화/과잉 타격.
- `raidSettlementConsistency.test.ts`: 실제 API 제출, 다른 참가자의 처치 경계, 지급 상한, 저장 실패/재접속, 원정 일부 사망 편성, 소탕/최고점 보상 영수증.
- 기존 `raidSubmission`, `stateRecovery`, `expeditionBossSubmission` 등과 전체 단위 테스트 및 빌드.
- 실제 Phaser 전투를 모바일 390×844 세로 화면에서 캡처해 HUD/결과의 위치와 점수를 확인한다.
