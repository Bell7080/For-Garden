## 작업 중 추가된 게스트 정리 마이그레이션

푸시 직전에 추가된 main `70513a30`과 아르테 전투 조정 `6721aff1`도 통합했다. 당시 새 `20261126000000_guest_cleanup.sql`은 QA·운영 모두 미적용이었다. QA 적용 요청을 자동 승인 검토가 거절했다. 계정 삭제 경로, 길드 삭제·위임 트리거, 친구 추천 조건 변경에 대한 명시적 승인이 부족하다는 사유다. 사용자에게 두 환경의 적용 승인을 요청했고, 승인 전에는 우회 적용하지 않았다. 이후 아래 후속 승인에 따라 완료했다.

최종 v0.457.2는 타입 검사·일반 빌드 통과, 단위 테스트 505파일·5,687개 통과(1개 건너뜀). 최신 전투 조정에 맞춰 궁극기는 광역 타격·아군 보호 모티프를 함께 넣고 폭주의 얼음 표현을 삭제했다. 최종 WebP 네 장은 빌드 산출물과 SHA-256이 일치한다.

### QA 검증

- 임시 계정 6개, 길드 2개, 결제 기록 1개와 운영진 역할 1개를 트랜잭션 안에서 만들고 마지막에 롤백했다. 테스트 계정 생성 시 사용한 UID 시퀀스 번호는 PostgreSQL 특성상 되돌아가지 않으며 계정·길드·결제 데이터는 남기지 않았다.
- 연동 계정·운영진 계정은 로그아웃 정리 대상에서 제외됨을 확인했다.
- 결제 게스트는 숨기되 삭제 요청을 만들지 않고, 미결제 게스트는 하루 유예 삭제 요청을 만드는 것을 확인했다.
- 180일 미접속 후보에서 최근 활동자·결제·운영진·연동 계정이 빠지는 것을 확인했다.
- dry-run이 삭제하지 않음, 30일 미만 거절, 실제 정리 시 길드장이 부길드장에게 위임됨, 혼자 남은 길드 삭제를 검증했다.
- 실제 정리 검증은 후보가 임시 계정뿐인지 먼저 검사한 뒤 실행하고 모두 롤백했다. QA에는 정기 삭제 예약을 추가하지 않았다.

### 운영 삭제와 예약

- UID `100000034`, `100000035`, `100000037`, `100000038` 네 개 모두 게스트·미결제·비운영진이며 길드장이 아니었다.
- 삭제 트랜잭션에서 사용자·플레이어 행을 잠그고 결제 기록의 동시 추가를 막은 뒤 보호 조건을 재검사했다. 네 개가 모두 조건에 맞지 않으면 전체 취소하도록 했다.
- 갱신 토큰과 세션을 지우고 `auth.users` 네 개를 삭제했다. 플레이어 및 관련 데이터는 외래키 연쇄 삭제를 따르며, 삭제 후 대상 UID 잔여는 0개다.
- 운영의 180일 dry-run 후보는 0개였다. 추가 장기 미접속 계정을 즉시 일괄 삭제하지 않았다.
- 운영 cron job `purge-inactive-guests`(ID 3): `30 3 * * *`, `select public.purge_inactive_guests(180, false);`, postgres 역할, active=true.
- 서버 cron 시간대는 GMT이므로 매일 03:30 UTC = 12:30 KST다. 기존 `purge-deleted-accounts` 예약은 유지했다.
- 조회·일괄 정리 함수는 service_role만 실행할 수 있고, 로그아웃 알림 함수는 authenticated 실행 허용·anon 실행 차단을 확인했다. 모두 빈 search_path를 사용한다.
- 두 환경 보안 advisor ERROR는 0개다. 기존 SECURITY DEFINER·익명 로그인·유출 비밀번호 보호 WARN은 남아 있다.
